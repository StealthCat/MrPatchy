# Requirements, correctness, and security review

Reviewed baseline: [`2cca1875d0c5da4a699c80dc6fdcfb80f59f2cd4`](https://github.com/StealthCat/MrPatchy/commit/2cca1875d0c5da4a699c80dc6fdcfb80f59f2cd4).

The implementation has the main architecture requested, but the original claim of comprehensive repository management is not met. Several monitoring, trust, and patch-selection defects also need correction before relying on it. This review includes regression-tested fixes on `review/requirements-security`; those fixes are not on `main` until the pull request is merged.

## Findings and proposed corrections

P1 = high-impact correctness/security failure; P2 = material reliability/hardening issue. Locations below point to the reviewed baseline so the original defect remains inspectable.

| ID | Severity | Finding and concrete trigger | Proposed correction |
|---|---|---|---|
| R01 | P1 | [Central host lock](https://github.com/StealthCat/MrPatchy/blob/2cca1875d0c5da4a699c80dc6fdcfb80f59f2cd4/app/worker.py#L83) and [target bridge lock](https://github.com/StealthCat/MrPatchy/blob/2cca1875d0c5da4a699c80dc6fdcfb80f59f2cd4/target/bridge.py#L94) prevent snapshot reads during long refresh/patch jobs. A target can disappear from monitoring precisely during maintenance. Multiple jobs for one host also consume both job slots. | Read atomic telemetry independently of mutation locks; skip conflicting inventory reconciliation while a job owns the host. Serialize mutations and schedule at most one active job per host. |
| R02 | P1 | [Ingestion](https://github.com/StealthCat/MrPatchy/blob/2cca1875d0c5da4a699c80dc6fdcfb80f59f2cd4/app/worker.py#L59) ignores `telemetry.errors`; an unchanged snapshot suppresses a newly reported collector error; future hash timestamps are treated as current. The UI can show a healthy server with incomplete or invalid evidence. | Surface collection/descriptor errors, re-evaluate repeated snapshots, reject invalid timestamps, flag future hash times. Verify managed ownership/modes as well as bytes. |
| R03 | P1 | [APT preparation](https://github.com/StealthCat/MrPatchy/blob/2cca1875d0c5da4a699c80dc6fdcfb80f59f2cd4/app/apt.py#L62) clears global trusted-key directories but retains scoped `/etc/apt/keyrings` and `/usr/share/keyrings` copies. A key removed from the target remains available centrally. | Rebuild every captured key directory for each refresh; removed trust material cannot silently survive. |
| R04 | P1 | [Atomic writes](https://github.com/StealthCat/MrPatchy/blob/2cca1875d0c5da4a699c80dc6fdcfb80f59f2cd4/target/bridge.py#L33) pass mode 0644 to `os.open`, but `main()` sets umask 077. Uploaded public keys actually become 0600 and cannot be read by APT's sandbox user. Existing files overwritten by the bootstrap can also retain a non-root owner. | Explicit final `fchmod`; unique temporary files and atomic replacement; bootstrap explicitly creates root-owned files/directories, validates sudoers before replacement, and creates the dedicated group. |
| R05 | P1 | [Inventory reconciliation](https://github.com/StealthCat/MrPatchy/blob/2cca1875d0c5da4a699c80dc6fdcfb80f59f2cd4/app/worker.py#L22) clears only candidates exactly equal to installed. An external upgrade from 1 to 3 leaves candidate 2 advertised. [Patch submission](https://github.com/StealthCat/MrPatchy/blob/2cca1875d0c5da4a699c80dc6fdcfb80f59f2cd4/app/main.py#L146) ignores a failed latest refresh, changed sources and queue-time drift. | Native version comparison clears obsolete candidates; changed inventory invalidates freshness. Reject failed/stale metadata, compare UI-reviewed candidate versions and revalidate fresh inventory/holds/candidates immediately before installation. |
| R06 | P1 | [Package/repository UI](https://github.com/StealthCat/MrPatchy/blob/2cca1875d0c5da4a699c80dc6fdcfb80f59f2cd4/app/static/app.js) uses mutable global `selected` across asynchronous requests and confirmation callbacks. A late response for server A can populate server B's view; actions can use the wrong current target/version. | Capture the host ID per view/action, discard stale/detached responses, sequence package queries, and submit the reviewed version map. |
| R07 | P2 | [Polling exception handling](https://github.com/StealthCat/MrPatchy/blob/2cca1875d0c5da4a699c80dc6fdcfb80f59f2cd4/app/worker.py#L83) commits after ingestion fails. A malformed later process can leave earlier package/behavior changes committed. A database error during a job can also leave its session unusable and job status stuck. | Roll back failed units of work before separately recording failure; reload records and surface worker exceptions. |
| R08 | P2 | [MySQL timestamps](https://github.com/StealthCat/MrPatchy/blob/2cca1875d0c5da4a699c80dc6fdcfb80f59f2cd4/app/db.py#L22) compile to single-precision `FLOAT`. Around current epoch values the spacing is 128 seconds; a reproduced value shifted by 26.25 seconds. This distorts last-seen times, job ordering and deadlines. | Use `DOUBLE` and an idempotent MySQL migration before workers start. Previously lost precision is unrecoverable; new observations refresh it. |
| R09 | P2 | [SSH response reading](https://github.com/StealthCat/MrPatchy/blob/2cca1875d0c5da4a699c80dc6fdcfb80f59f2cd4/app/ssh.py#L27) reads stdout without draining stderr. | R10 | P2 | [Source validation](https://github.com/StealthCat/MrPatchy/blob/2cca1875d0c5da4a699c80dc6fdcfb80f59f2cd4/app/apt.py#L32) rejects unsafe directives even in disabled/comments, blocking repair by disabling them. | R11 | P2 | [Behavior identity](https://github.com/StealthCat/MrPatchy/blob/2cca1875d0c5da4a699c80dc6fdcfb80f59f2cd4/app/worker.py#L51) omits listener bind addresses; changing a service from loopback to all interfaces can retain approval. ## Remaining gaps and improvements

1. **Complete repository support is still absent.** Add explicit central credential/CA/proxy handling and a source-by-source health model. Avoid copying arbitrary target APT hooks; model supported configuration declaratively. Plan transport adapters/mirroring for local repositories rather than pretending they are remotely reachable.
2. **Broken package states need an inventory model.** Preserve dpkg state, surface unpacked/half-configured/reinstreq conditions, and design separately reviewed recovery operations. Current filtering can hide precisely the packages needing repair.
3. **AI is triage, not an investigation engine.** Add bounded, read-only evidence collection (package ownership/provenance, service unit, executable metadata, threat indicators), explicit investigation states and queue/backlog visibility. Never let model-supplied shell commands run as root. Keep API credentials central and make data disclosures clear.
4. **Observation delivery is lossy.** The collector overwrites its latest snapshot. A durable bounded event spool with acknowledgements would preserve new process/connection events across delays and outages. Namespace coverage, short-lived processes and interpreted code need separate design decisions.
5. **The integrity baseline has limits.** Root/kernel compromise can forge procfs and collector results; hashing is not remote attestation. OS package-file integrity would require verified package artifacts/manifests and careful configuration-file policy. No such full-system verification exists today.
6. **Availability and scale need stronger controls.** Add pagination, retention/archiving, per-host queue limits, subprocess output/disk quotas, jitter, metrics and cancellation. Offline targets cannot get fresh central repository candidates until SSH returns. A separate durable worker process would improve shutdown/crash behavior and multi-replica safety.
7. **Authentication is single-administrator.** Expired session/enrollment rows are not routinely removed. Login throttling sees the network peer; behind the default proxy, users share a bucket, and successful logins also count. Add tested trusted-proxy handling, failed-attempt accounting, rotation/revocation UI and optional MFA/RBAC before broader exposure.
8. **Some admin data can outgrow MySQL TEXT.** Central APT/job output is captured before truncation and some successful output is not truncated at all. Large output can consume memory or exceed MySQL TEXT's byte limit. A bounded log store and explicit retention are preferable to expanding database fields blindly.
9. **Network trust needs explicit deployment policy.** Internal HTTP(S) repositories are intentionally allowed; a compromised enrolled target can influence central outbound requests. Use management-network egress controls; consider per-host repository allowlists. Target-provided signing keys are trusted through SSH enrollment, not independently authenticated publisher provenance.
10. **Real deployment validation is still required.** Docker fixtures use a systemctl stub. Actual systemd reboot persistence, Raspberry Pi ARM hardware, real package upgrades, live custom-ACME issuance and long-running multi-host load have not been established by those tests.

## Validation and evidence

- The first 16 newly added regression cases all failed against the unchanged baseline, establishing reproducible failures rather than only speculative findings.
- **61 local pytest tests passed; one live-MySQL migration test was explicitly skipped on SQLite.** Real SSH protocol tests, syntax checks and the native signed ARM64 repository test passed. The desktop/mobile browser smoke test also passed, including a delayed-response target-switch regression and reviewed-version submission.
- Post-update `pip-audit` reports **no known vulnerabilities** in the resolved production requirements. This is an advisory-database result, not a proof that no vulnerabilities exist.
- Follow [PR #1 checks](https://github.com/StealthCat/MrPatchy/pull/1/checks) for the final MySQL, Compose runtime, browser and Ubuntu/Debian SSH integration outcomes.
- A live MySQL test is explicitly skipped on local SQLite and included in the new MySQL CI job. It alters a disposable test column to legacy FLOAT, runs migration, and checks exact fractional-second storage.
- New CI tests boot the Compose stack and validate HTTPS with its generated CA, and exercise offline enrollment, real OpenSSH/sudo, root ownership, key modes, host pinning and snapshot reads during a held mutation lock in Ubuntu/Debian containers. Service-control calls are stubbed; this is not real systemd validation.
- Bandit findings were manually triaged: its Paramiko shell-injection warning concerns a constant `mrpatchy` command followed by JSON input to a forced command, not interpolation of user input into a shell. Subprocess uses are argv-based. The placeholder-password finding points to explicit rejection of that placeholder. Static analysis is not a proof of security.
- Dependency advisory references: [GitHub advisory](https://github.com/advisories/GHSA-r374-rxx8-8654), [upstream RSA/SHA-1 removal](https://github.com/paramiko/paramiko/commit/a4489456b6f65281e172380cc4826cee5e851dbb).

## Applying the reviewed fixes

Back up the database and app/TLS volumes before upgrading. After merging/rebuilding, MySQL's timestamp migration runs at startup; it requires ALTER privileges for the app's schema. It cannot reconstruct old rounded timestamps.

For existing v0.1 targets, download the new personalized offline installer, run it once through a trusted console, then choose **Finish / repair installation**. This replaces the legacy bridge and permits future managed bridge/collector/unit deployments. Until updated, missing integrity metadata is shown as attention and a legacy-bridge deployment does not report success.

Review newly generated behavior identities after the effective-UID/bind-address change. Existing approvals are retained as historical records; they are not silently copied to changed identities. No live target operations or paid API requests are performed by this code review.
