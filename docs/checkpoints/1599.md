# Checkpoint: #1599 LVM2 program contract (roadmap F slice)

## Increment 1: pure contract

`app/lvm_commands.py` takes observed records for `/etc/lvm/lvm.conf`, `lvmlocal.conf` and any
`lvm_<tag>.conf`, plus the node name. It reports the effective value and source of each LVM2
2.03.16 setting that names a program or plugin run as root:

- the thin/cache check, dump and repair executables, `vdo_format_executable` and `fsadm_executable`;
- `lvmlockctl_kill_command`;
- `dmeventd/executable`;
- the five `dmeventd/*_library` plugins, which are loaded with `dlopen()`;
- `dmeventd/thin_command` and `vdo_command`. Each is classed as an internal `lvm` command, an
  external program (the whole value is `argv[0]`, then `vg/lv`) or invalid.

Semantics are ported from lvm2 `v2_03_16`:

- the `device_mapper/libdm-config.c` tokenizer, grammar and `_config_reverse()` file order;
- the `lib/commands/toolcontext.c` cascade and tag rules: `hosttags`, `host_list` (values checked in
  order as `_check_host_filters` does: the first matching string passes, and only a non-string
  reached before a match fails), an error on `host_filter`, and tag-name validation;
- `merge_config_tree(CONFIG_MERGE_TYPE_TAGS)`, including the section `tags` filters;
- the `_find_config_str()` fallbacks for wrong-type and forbidden-empty values;
- `dmeventd_thin.c` command registration.

The contract does no I/O, runs nothing and authorizes nothing. The origin is `not_assessed`.

## Evidence

- The packaged files come from Ubuntu 24.04 `lvm2_2.03.16-3ubuntu3.2_amd64.deb`. The sha256 of
  `lvm.conf` is `ef4955e4c81761bdd6cb37c73c54b80b3a6ce04288baccb2238c05f016d6c91b` and of
  `lvmlocal.conf` is `6034be4f1d62cadb9fec2e7c5f1a7592f44ef21b2bebc70585eac940f0da6f88`.
- A native differential ran the extracted `lvm lvmconfig --typeconfig full` with `LVM_SYSTEM_DIR`
  pointed at a scratch directory and node name `vm`. It covered 35 cases. The contract agreed on
  every effective value and on every load failure: parse errors, an unbalanced brace,
  `host_filter` and an invalid tag.
- That run found and fixed two porting mistakes: tag order (the tree is reversed back into file
  order after parsing) and arrays (only the first value is read).
- `lvmconfig` prints the raw value for wrong-type and empty-not-allowed settings. The runtime
  `_find_config_str()` uses the build default instead, and the contract follows the runtime. The
  tests document this.
- `tests/test_lvm_commands.py` has 16 tests.

**Compatibility:** new files only. There is no schema, route, auth, agent, scheduling or
response-authorization change.

## 2026-11-27 — increment 2: collector capture

**Delivered** (branch `claude/magical-goodall-sfh17w`): agents hash the LVM configuration cascade's two
fixed files as built-in startup scope. Nothing is parsed or run; they are metadata and SHA-256 only, like
the other built-in startup files.

- `target/agent.py`: `/etc/lvm/lvm.conf` and `/etc/lvm/lvmlocal.conf` join `PERSISTENCE_FILES` and
  `PROMOTED_PERSISTENCE_FILES`. The `/etc/lvm` directory itself is **not** built-in scope: its `archive/`,
  `backup/` and `cache/` directories hold LVM metadata backups that would consume the 256-entry inventory
  budget, and they configure nothing that runs.
- New `NESTED_PERSISTENCE_FILES`: these are the first built-in files inside a directory an administrator
  could already store as a custom path. A saved custom `/etc/lvm` (or `/etc/lvm/profile`,
  `/etc/lvm/archive`, ...) therefore stays valid instead of failing the overlap check after an upgrade. Its
  traversal skips the two built-in files, so each is inventoried once. A stored `/etc/lvm/lvm.conf` or
  `lvmlocal.conf` is promoted, as with earlier built-in files. `/etc`, `/` and paths overlapping each other
  are still rejected.
- `app/persistence.py`: both files are additive built-in scope. `compare()` now treats an entry as
  previously observed when it lies within the earlier inventory's scope (equivalent to the old rule for
  every earlier case), so a custom `/etc/lvm` baseline keeps comparing `lvm.conf` instead of reporting it
  removed, and such files are not listed as newly covered.
- `app/startup_inventory.py` labels the files (`lvm`, `lvm_local`) and states the gap: the programs the
  cascade names are not yet evaluated, and host-tag files `lvm_<tag>.conf`, profiles, archive/backup/
  cache/devices, `--config`/`LVM_SYSTEM_DIR` and initramfs copies are not observed.
  `app/startup_catalog.py` adds the `lvm` event mechanism.

**Validation:** `tests/test_lvm_scope.py` (23 cases) fails 12 on main `22e1a24` and passes with the
change. They cover hashing without walking backups or running anything, absent files, stored custom paths
(directory, subdirectory, file and promoted file), rejected overlaps, single inventory of nested files,
comparisons against earlier built-in, custom-directory and custom-file baselines, non-additive
neighbours, catalog labels, a saved monitor policy with `/etc/lvm` and the startup view. The 27 related
startup/persistence/scope suites pass (917 tests), as do the CI ruff selections, compileall and
`check_version --allow-unversioned`.

**Compatibility:** no schema, route, UI, auth, scheduling or response-authorization change. Agents that
report the new files add at most two entries on hosts with LVM installed. Older agents keep their scope.

**Remaining for #1599:** host-tag file collection (needs the node name and a bounded `lvm_*.conf`
listing), agent-side parsing through `app/lvm_commands.py` with the Startup Files display, provenance, AI
classification, `lvmlockctl --kill` execution form and non-Ubuntu build defaults.

## 2026-11-28 — increment 3: agent parsing and the Startup Files display

**Delivered** (branch `claude/magical-goodall-4s63qc`): agents parse `/etc/lvm/lvm.conf` and
`/etc/lvm/lvmlocal.conf` from the hashed bytes. The controller evaluates the cascade with
`app/lvm_commands.assess`, and Startup Files shows the result on the `lvm.conf` row.

- `target/agent.py` `parse_lvm_conf`: a copy of the contract's libdm-config tokenizer and parser.
  It reports only a reduced tree:
  - the `global/*` and `dmeventd/*` program settings;
  - each of those sections' `tags` filter, including a `tags` subsection, which makes the merge
    skip the section;
  - the `tags` section: `hosttags`, the tag subsections and their `host_list`/`host_filter`;
  - the node name from `uname(2)`.

  Every other value is dropped. Command settings (`lvmlockctl_kill_command`, `thin_command`,
  `vdo_command`) get the cron best-effort redaction. Strings are capped at 512 characters and
  arrays at 64 values. Any redacted or cut value is listed as `inexact`. A file the parser rejects
  keeps only its reason and line. A file with NUL bytes or invalid UTF-8 keeps only that reason.
- `app/persistence.py` `validate_lvm`: a strict schema. It accepts only retained keys, typed
  values, bounded text, no NUL bytes, no duplicates and known error reasons. A rejected file
  cannot carry settings. The new key is excluded from `metadata()` comparisons.
- `app/lvm_commands.assess`: a record can now carry `parse_error` from an agent. It produces the
  same gaps and `lvm_starts=False` as a parse of the full text. This is additive, so the contract
  version stays 1.
- `app/startup_inventory.lvm_view`: rebuilds canonical text (every key and string quoted and
  escaped) and runs the contract. The following are blocking gaps:
  - files not reported by older agents;
  - symlinks, which are not followed;
  - an unrecorded `lvmlocal.conf` in an incomplete collection, reported as unknown;
  - inexact values;
  - `lvm_<tag>.conf` files, which are not collected yet.

  The catalog row says when settings were evaluated, when a file was rejected and when a file was
  not reported. Search covers the retained string values.
- `app/static/server.js` `startupLvm`: a settings table showing each value, trigger, execution
  mode and source, with a rejected-file notice and coverage gaps. All text is escaped.

## Evidence (increment 3)

- `tests/test_lvm_agent_view.py` (39 cases) compares the agent→validator→view path with the
  contract run on the full original text: settings, tags, warnings, gaps, files and `lvm_starts`.
  - 24 hand-written cases, each run as `lvm.conf`, as `lvmlocal.conf` and without a node name.
    They include parse errors, path keys, a `tags` subsection filter, hosttags, host_list order,
    host_filter, wrong types, arrays and escapes.
  - A seeded 600-case random grammar with corruptions; more than 20 of its cases are parse errors.
  - Mutation cases for the validator.
- A local sweep of 20,000 further random cases (40 seeds) found no divergence. It found and fixed
  one porting mistake before that: a top-level node holding both a value and children was skipped.
- `tests/ui_startup_lvm.cjs` renders the real view output at 320, 768 and 1440 px. It checks
  escaping, the rejected-file notice, gaps, the older-agent text and the Coverage label.

**Compatibility:** additive. Older agents' inventories show "not reported by this agent version".
There is no schema, route, auth, scheduling or response-authorization change.
