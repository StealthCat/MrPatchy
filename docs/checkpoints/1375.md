# #1375 — autofs program-map contract (roadmap F slice)

## Increment 1 (delivered earlier)

PR #1376 delivered `app/autofs_program_maps.py`, the pure resolution contract that maps master-map entries to the program maps automount runs as root. The contract follows autofs 5.1.9 `lookup.c`, `lookup_program.c` and `master_tok.l`.

## 2026-11-27 — increment 2: built-in collection of `/etc/auto.master`

**Delivered:** `/etc/auto.master` joins built-in startup scope. This follows the increment-2 pattern already reviewed for #1390, #1530, #1535 and #1538.

- `target/agent.py`: `PERSISTENCE_FILES` hashes the file as metadata only. A symlink is recorded, not followed. Nothing in the file is parsed and no map program is run. `PROMOTED_PERSISTENCE_FILES` keeps a saved custom path equal to the file valid, and the file is inventoried once.
- `app/persistence.py`: `ADDITIVE_BUILTIN_SCOPE` keeps a baseline from an older agent comparable. The file is listed as `newly_in_scope` / `not_in_baseline`, never as `added`. Neighbouring paths stay non-additive, and so do downgrades. The neighbouring paths are `/etc/auto.master.d`, `/etc/auto_master`, `/etc/auto.misc`, `/etc/autofs.conf`, `/etc/default/autofs`, `/etc/sysconfig/autofs` and `.rpmnew`.
- `app/startup_inventory.py`: the label "autofs master map" and a coverage gap.
- `app/startup_catalog.py`: a metadata-level `autofs` mechanism that is event-triggered, system-scope and present on both families. Ubuntu builds autofs `--with-mapdir=/etc`, and RHEL ships `/etc/auto.master`.

**Scope choice:** `/etc/auto.master.d` and the map files are left out on purpose. Adding a directory, or a path below a directory an administrator may already have saved as a custom path, would make that saved monitor policy fail the overlap check after an upgrade. `/etc/auto.master` sits directly under `/etc`, which already overlaps built-in scope, so only an exact saved path is possible, and promotion handles it.

**Validation:** `tests/test_autofs_scope.py` has 19 tests. 7 fail on main `c125801` and all 19 pass on the branch. In the agent test, the master map names a program map that would create a marker file, and the test asserts the marker never appears. A mutation that makes `/etc/auto.master.d` additive instead of `/etc/auto.master` fails 5 tests. 577 related tests pass, and so do ruff (CI selections), `git diff --check` and `check_version --allow-unversioned`. A trial merge with draft #1631 (kdump hooks, same modules) is clean, and 123 combined tests pass.

**Remaining:** agent-side parsing of the hashed master map into entries and program-map resolution through `autofs_program_maps`, with strict controller validation and the Startup Files display. After that: `auto.master.d` and map-file coverage, provenance and AI classification.

## 2026-11-27 — increment 3: program maps resolved from the reported master map (PR #1641, draft)

**Delivered so far:** agents that parse startup jobs report the hashed `/etc/auto.master` bytes as bounded text (64 KiB, latin-1, no NUL bytes) plus a read-only `stat` of each candidate map path (at most 128, within the deadline). Paths at or below any possible mount point are never stat-ed, because a lookup there can mount a map or run a program map. `persistence.validate_autofs` validates the report strictly, and metadata comparisons exclude it. `startup_inventory.autofs_view` resolves it through `autofs_program_maps.evaluate_master`, so the agent does not duplicate the grammar. Startup Files renders the entries, the program maps and the gaps.

**Fail-closed:** the result is never complete. Blocking gaps cover nsswitch `automount:` sources, `autofs.conf`, truncated stats, unobserved paths, unread text maps, includes and remote sources. `origin` is `not_assessed` and nothing authorizes a response.

**Validation:** 30 new tests error at collection on main `1733d1e` and pass on the branch. Removing the mount-point exclusion fails 2 of them. 557 related tests pass. The Playwright module passes at 320/768/1440 px.

**Remaining:** merge main after #1640 lands (12 additive conflicts with the kdump hooks), then hand off. After that: capture of `auto.master.d`, includes and text maps; nsswitch and `autofs.conf` observations; provenance; AI classification; native acceptance.
