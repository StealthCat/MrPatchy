# Repeated fixture benchmarks at fixed concurrency (Roadmap A, #1548)

## 2026-11-26

Use the same synthetic workload, database version and worker count for each
baseline/candidate capture. Record the source commits alongside the reports.
Pair each before/after capture and alternate which checkout runs first where
possible.

```bash
python tools/compare_ai_benchmark_series.py --fixed-concurrency \
  --pair baseline-1.json candidate-1.json \
  --pair baseline-2.json candidate-2.json \
  --pair baseline-3.json candidate-3.json
```

The series uses the existing one-pair fixed-concurrency checks, including
workload and database-version equality. It also requires stable settings and
capability across the series and rejects reused inputs. Fixed-concurrency JSON
labels configurations and reports as baseline and candidate. Signed deltas are
candidate minus baseline. Commands without the flag still compare serial and
parallel and retain the existing JSON field names.

On main `2c3615ee789e6431e955087697e6ec94785827f3`, the four new focused
cases fail because the series command does not recognize the flag. They pass
with this change along with the existing single-pair and series tests.

Three independent SQLite pairs compared `0a5c68b` with `2c3615e` at four
workers, three fixture servers and the same daily-cap workload. Each capture
accepted eight subjects, 12 synthetic provider calls and four simulated SSH
follow-ups. The comparison matched the workload fingerprints, token counts and
settled fixture budget. These results validate the comparison using disposable
fixtures. Roadmap A production measurements remain open.
