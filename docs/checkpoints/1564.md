# Checkpoint: pam_namespace init-script contract (#1564)

Roadmap F (startup and scheduled-task awareness), issue
[#1564](https://github.com/StealthCat/MrPatchy/issues/1564).

## 2026-11-26 — increment 1: pure contract

**Delivered** (branch `claude/vibrant-tesla-g3wmiw`): `app/pam_namespace_init.py`, a pure
contract. It takes captured `/etc/security/namespace.conf` text, a captured
`namespace.d` listing and files, the observed state of each init script and, optionally,
the `pam_namespace.so` module arguments. It reports which program `pam_namespace` runs as
root for each polyinstantiated directory on every session open:

- `/etc/security/namespace.init` or the per-directory `iscript=` program. A relative
  `iscript=` resolves under `namespace.d/`. The last non-empty value wins, flags match by
  prefix and `noinit` suppresses the script;
- the argv: script, polydir, instance (`tmpfs` for the tmpfs method), `newdir`, user and,
  in the 1.7 model, the two safe-path flags. It runs with an empty environment, libpam waits
  for it and ignores its exit status;
- read order: `namespace.conf`, then `namespace.d/*.conf` in `strcmp` basename order,
  skipping hidden names;
- each invalid line and its reason. Without `ignore_config_error` it fails every session,
  and so does a missing `namespace.conf`, even when drop-ins exist. A script that exists
  but is not executable stops the session at its directory, after the earlier scripts ran;
- override-user lists (`~` exclusive) and `$HOME`/`$USER` expansions.

Unobserved files, listings and script states, NUL bytes, over-limit input, a vendor
directory, an unknown model, a method with no name (libpam calls `strcmp(NULL, …)` and
the process crashed natively) and `create` owner/group accounts are gaps. A result with
any gap is not `complete`. `origin` is `not_assessed` and `authorizes_response` is always
false.

**Validation:** 41 tests in `tests/test_pam_namespace_init.py`. The cases marked native
replay runs of Ubuntu 24.04 `libpam-modules 1.5.3-5ubuntu5.7`, whose pam_namespace is
synced to Linux-PAM 1.7 with the CVE-2025-6020 fixes. A ctypes `pam_open_session` driver
ran `session required pam_namespace.so [args]` inside `unshare -m`, and logging init
scripts recorded argv and environment. The `1.5` model applies the documented 1.5.3
source differences (four arguments, `/` polydir invalid, one trailing slash removed). It
has not been run natively.

**Compatibility:** new files only. No schema, route, UI, auth, scheduling, agent or
response-authorization change.
