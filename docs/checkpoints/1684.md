# #1684 — Expose API-only administrator features in the UI

## Review method

Every `@app.<method>('/api/…')` route in `app/main.py` (258 routes) was checked
against the calls in `app/static/*.js`. That includes calls that build paths with
template strings and string concatenation, and the `api()` helper's `/api` prefix.
The routes left over after that check were confirmed by hand. README.md described
several of them as "API-only".

## Delivered

| Feature | Endpoints | UI location |
|---|---|---|
| Saved fleet queries | `GET/POST /api/fleet/queries`, `PUT/DELETE …/{id}`, `GET …/{id}/results` | Servers → Saved queries (every role can list and run; administrators can create, edit and delete) |
| Change freezes | `GET/PUT /api/operations/freezes` | Patch schedules → Change freezes |
| Application probes | `GET/PUT /api/operations/{host}/probes` | Server → Maintenance → Application probes |
| Agent spool batch size | `PUT /api/operations/{host}/spool` | Server → Agent health → Event spool batch size |
| SSO identity bindings | `GET /api/operations/sso-bindings`, `DELETE …/{digest}`, `PUT /api/operations/sso-binding` with `replace_username` | Users → Single sign-on identities |
| Recovery readiness receipts | `GET /api/recovery/readiness`, `POST /api/recovery/receipts` | Settings → Backup & recovery |
| AI connection inventory | `GET /api/settings/ai-connections` | Settings → AI & models → Where AI is used |
| Incident case owner and notes | `GET …/incidents/{id}/case`, `PUT …/owner`, `POST …/notes` | Server → Security → incident → Owner & notes |

Settings also gains an **Alerts & sign-in** section. It links to the alert delivery,
enterprise controls (SMTP, SSO binding, key rotation) and staged-rollout dialogs.
Before this change those dialogs could only be reached through Account → Operations.

## Readability fixes

- Each sidebar item now has its own icon. Available patches, Package history,
  AI run logs, File status and Users used to share icons with other items. The
  icons also appear in page eyebrows.
- `.actions` rows centre their items vertically, so pager labels such as
  "Page 1 of 1" line up with the Previous and Next buttons.
- Long or rarely used forms (SSO bind, recovery receipt) are collapsed behind a
  disclosure.

## Boundaries

Every panel calls an existing endpoint and keeps its role checks, revision or
version preconditions, validation and audit records. No backend, schema,
authentication, scheduling or response-authorization code changed. The only
panel that contacts a target is spool batch size, which uses the existing endpoint
and its readback verification. Recording a recovery receipt does not start a
backup or restore. Incident ownership and notes do not change incident state or
response plans.

## Validation

- `tests/ui_admin_tools.cjs` (added to `tests/ui.cjs`) covers create, run, edit,
  stale-version refusal and delete for saved queries. It also covers freeze
  validation, saving, and the stale-revision refusal, saving HTTP and TCP probes,
  spool success and an unconfirmed target, and SSO unbind and replace after a
  conflict. Recovery receipt recording, the AI inventory, the Alerts & sign-in
  links, and incident owner conflict and note recording are covered too.
- `tests/test_settings_index_search.py` now covers the two new Settings
  sections. `tests/test_ui_agent_confirm.py` stubs the new module in its
  isolated harness.

## Remaining

- README still calls saved fleet queries, change freezes and incident case
  ownership "API-only". The coordinator should apply the README text proposed in
