# Checkpoint: syslog-ng command contract (#1570)

Roadmap F (startup and scheduled-task awareness), issue
[#1570](https://github.com/StealthCat/MrPatchy/issues/1570).

## 2026-11-26 — increment 1: pure contract

**Delivered** (branch `claude/vibrant-tesla-pyny09`): `app/syslog_ng_programs.py`, a pure
contract. It takes captured syslog-ng configuration text and captured include directory
listings, and reports each command syslog-ng 4.3.1 runs:

- `program()` sources and destinations, run as `/bin/sh -c <string>`. A source is restarted
  when it exits, and a destination receives every routed message;
- `hook-commands()` `setup`/`startup` (when the driver starts) and `teardown`/`shutdown`
  (when it stops) commands, run as `sh -c -- <string>`;
- `@module confgen` generators, run as `sh -c -- <string>` when a source or destination uses
  them. The contract records a blocking gap because the generated configuration is not observed;
- each command's file, line, owning source/destination, status and argv.

Status is one of four values: `runs` (a `log` path references the driver, by name or inline),
`not_referenced`, `rejected` (syslog-ng would refuse the configuration) or `unresolved`.
The contract models the string lexer (double-quoted escapes, literal single quotes),
`@define`/backtick expansion in configuration order, and `@include` search through
`/etc/syslog-ng:/usr/share/syslog-ng/include`. It also models sorted glob and
safe-name directory expansion, missing-include, unresolved-reference and duplicate-definition
failures, and the adjacent-string syntax error. The daemon runs as root by package default;
`--user` on the command line is listed as not observed.

Unobserved files or listings, invalid UTF-8, NUL bytes, over-limit input, syntax errors,
unresolved backticks in a running command (built-ins such as `scl-root` and environment
variables), referenced `block` drivers, running confgen generators, `allow-config-dups`,
nested directories and ambiguous relative globs are blocking gaps. A result with any gap is
not `complete`. `origin` is `not_assessed` and `authorizes_response` is always false.

**Validation:** 25 tests in `tests/test_syslog_ng_programs.py`. They replay native runs of
Ubuntu 24.04 `syslog-ng-core 4.3.1-2build5` (`syslog-ng -F` as root, with a probe that
recorded its parent's command line and uid, plus `strace -e trace=openat,access,execve` for
include order, include-path search and the packaged configuration). Four of them form a live
differential that starts the real daemon when `MRPATCHY_SYSLOG_NG` is set and the tests run
as root. It passed locally against `/usr/sbin/syslog-ng`. The packaged Ubuntu configuration
runs SCL's `getvirtconsole` confgen (`tty10.sh`) as root, because `d_console_all` is used by a
log path. The contract reports that command as `unresolved`, with `scl-root` named.

**Compatibility:** new files only. No schema, route, UI, auth, scheduling, agent or
response-authorization change.

**Remaining under #1570:** agent collection of the configuration, includes, SCL and the
service command line (`-f`, `--user`, `--include-path`), resolving build-specific
backtick variables such as `scl-root` from the installed package, startup catalog and
provenance integration, UI, AI classification of the reported commands, and code that
python()/java() bindings load into the daemon.

## 2026-11-28 — increment 2: built-in startup scope

**Delivered** (branch `claude/confident-einstein-hu2air`): agents hash the `/etc/syslog-ng`
directory (syslog-ng.conf, conf.d, scl.conf, patterndb.d and any other files it holds,
including TLS keys, as metadata and SHA-256 only) and the Debian-family
`/etc/default/syslog-ng` and RPM-family `/etc/sysconfig/syslog-ng` option files (which supply
`SYSLOGNG_OPTS`, such as `--user` and `-f`) as built-in startup scope on both families. Nothing
in them is parsed or run, and no file content is stored.

- `/etc/syslog-ng` is a built-in root and a promoted root: a saved custom `/etc/syslog-ng`, or
  a path inside it, is accepted and inventoried once.
- Neither `/etc/default` nor `/etc/sysconfig` is built-in. The two option files are nested
  built-in files, as #1599 did for `/etc/lvm`: a saved custom `/etc/default` or
  `/etc/sysconfig` stays valid, and its traversal leaves the file to built-in scope. A saved
  custom path equal to one of the files is promoted.
- The paths are additive to earlier baselines. A file inside an earlier custom directory keeps
  comparing; others are listed as newly covered.
- Both startup catalogs label the paths (`syslog_ng`, `syslog_ng_defaults`,
  `syslog_ng_sysconfig`). A coverage gap says the commands are not yet evaluated in this view
  and names what is not observed: the SCL under `/usr/share/syslog-ng/include`, included files
  outside `/etc/syslog-ng`, options set in the unit or on the command line.

**Validation:** 46 tests in `tests/test_syslog_ng_scope.py` (17 fail on main `8d13a56`):
scope tuples, real agent hashing with planted `program()`/`hook-commands()` markers that never
run and a key that is never stored, absent paths, saved custom option directories, overlap and
non-canonical rejection, nested traversal, baseline comparison, promotion, catalog labels and
the startup-inventory API. `tests/test_lvm_scope.py` now checks only the LVM entries of the
shared nested-file tuple (the same edit as #1699).

**Compatibility:** additive scope only. No schema, route, UI, auth, scheduling or
response-authorization change. Agents report up to the directory's files and two more entries.

**Remaining under #1570:** agent parsing of the hashed bytes with the increment 1 contract
(including `SYSLOGNG_OPTS` `--user`/`-f`), SCL and `scl-root` resolution, the Startup Files view
of the commands and accounts, provenance and AI classification.
