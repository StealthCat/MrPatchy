# Native capped MySQL triage benchmark (#1617)

The **Native capped AI benchmark** workflow now runs separate SQLite and MySQL
jobs on Ubuntu 24.04. It uses the same six order-alternated serial/four-slot
pairs, follow-up evidence, synthetic provider pricing and acceptance comparator
on each backend. Both artifacts retain the raw captures and validated series.
The raw captures record the version of the database that served them.

The MySQL job starts a disposable MySQL 8.4 service and supplies the benchmark
with a dedicated schema and non-root account. The URL is scoped to the capture
step. Every invocation still acquires the benchmark's native database lock,
checks that the schema is empty and drops only its own fixture tables on exit.
The SQLite job does not start a MySQL service.

Manually dispatch **Native capped AI benchmark** and select a ref to compare
serial and parallel performance for each backend. A pull request changing the
workflow benchmarks its exact base commit. Download the two backend artifacts
separately. Compare across modes within each backend before comparing absolute
timings across jobs. The jobs can receive different hosted runners.

These captures measure a disposable loopback fixture. They do not measure
production throughput, remote MySQL network latency or production spend.
