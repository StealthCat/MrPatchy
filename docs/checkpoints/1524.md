# Issue #1524 — DKMS root-execution contract (roadmap F)

## 2026-11-25 — increment 1, worker checkpoint ([PR #1526](https://github.com/StealthCat/MrPatchy/pull/1526))

- **Outcome:** `app/dkms_hooks.py` is a pure, I/O-free contract. It reports which files `dkms` sources with bash as root, in order. Those are `/etc/dkms/framework.conf`, then `framework.conf.d/*.conf`, then each module's `dkms.conf`, then `/etc/dkms/<module>.conf`, `<module>-<version>.conf`, `-<kernel>.conf` and `-<kernel>-<arch>.conf`. It also reports the `POST_ADD`/`PRE_BUILD`/`POST_BUILD`/`PRE_INSTALL`/`POST_INSTALL`/`POST_REMOVE` program each module runs as root, with its directory and argv, and the `MAKE[n]`/`MAKE_MATCH[n]`/`CLEAN` commands dkms `eval`s as root. Every sourced file is reported as root shell code, not just its assignments.
- **Semantics:** `/usr/sbin/dkms` from Ubuntu 24.04 `dkms 3.0.11-1ubuntu13`:
  - **Re-parsing:** `safe_source` echoes each kept variable back unquoted and sources it again. Values are word-split, glob-expanded and re-parsed in double quotes, so a single-quoted `$(...)` runs as root.
  - **Hook paths:** `run_build_script` runs `$dkms_tree/<m>/<v>/{build|source}/<value>`, gated by `-x` on the first word and started with `exec $run`, without a shell. A value starting with `/` stays under that directory.
  - **Defaults:** `dkms_tree` defaults to `/var/lib/dkms` and can be moved by a literal framework assignment.
- **Native evidence:** dkms 3.0.11 ran as root in a disposable Ubuntu 24.04 container through `add`, `build`, `install`, `status` and `remove`, using a marker module and overrides.
  - It confirmed the source order, that the `noext` drop-in is skipped, that the override `POST_REMOVE` wins, and the `source`/`build` working directories.
  - It confirmed that `build//hook.sh` runs for an absolute value, and that whitespace is collapsed.
  - It confirmed the non-executable `post_install` warning, that a single-quoted `$(...)` is executed, and that a glob first word is not run.
  - It confirmed that `dkms status` sources built modules' `dkms.conf`.
  - Each observation is a case in `tests/test_dkms_hooks.py` (20 tests). Four mutations (no re-parse detection, wrong build directory, first-wins, no glob check) each fail the suite.
- **Fail closed:** values are `unknown` rather than absent for any of these:
  - a non-literal line (commands, expansions, functions, continuations, `~`, `DKMS_DIRECTIVE`);
  - a re-parsed or glob value;
  - an unknown `dkms_tree`;
  - an unobserved `/etc/dkms` listing or executable bit;
  - a kernel-specific override without a kernel context.

  Unobserved, unreadable, non-regular or oversized files are blocking gaps. `origin` is `not_assessed`, there is no safety verdict, and `authorizes_response` is always false.
- **Remaining (#1524):** native agent collection of `/etc/dkms`, `/var/lib/dkms/*/*/source/dkms.conf` and hook `-x` bits, plus a startup-catalog entry, package provenance, persistence, UI and AI classification. Which `MAKE[n]` a given kernel selects is not resolved.
- **Unchanged:** schema, agent, scheduling, AI, roles and response authorization.
