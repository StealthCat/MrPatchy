# #1535: system gitconfig execution contract (roadmap F slice)

## 2026-11-25: increment 1, pure contract

- **Roadmap item:** F, startup and scheduled-task awareness. `/etc/gitconfig` is an
  event trigger: every git invocation by any user, root included, reads it and can start
  the programs it names.
- **Delivered:** `app/git_system_config.py` and `tests/test_git_system_config.py`
  (branch `claude/gitconfig-contract-1535`, PR #1536). `parse_config` follows git 2.43 `config.c`;
  `assess_system_gitconfig` follows unconditional and conditional includes and reports
  `!` aliases, pagers, editors, `core.sshCommand`, `core.gitProxy`, `core.askPass`,
  `core.fsmonitor` hooks, `core.hooksPath`, credential helpers, diff/filter/merge,
  difftool/mergetool/browser drivers, gpg programs and `uploadpack.packObjectsHook`,
  each with key, file, line, include chain, condition, trigger, `via_shell` and
  environment override. `ext::` transport enablement is reported as a transport risk.
- **Validation:** 21 unit tests. Inner-whitespace handling depends on the git version (2.43 turns each character into a space; the newer git on the CI runner keeps it), and is modeled as `inner_whitespace`. Native git 2.43.0 differential checks compare the
  parser with `git config --system --list -z` on a ten-input corpus and confirm that git
  rejects all eight syntax-error inputs, that include resolution order matches
  `--includes --list`, and that 10 nested includes load while 11 are fatal. A
  behavioral run shows a system `!` alias, `core.pager` (on a pty) and a credential
  helper (`get`) actually executing. Mutation checks on comment handling, whitespace
  runs, helper reset, include depth and the `!` prefix each fail tests.
- **Remaining:** collection of the system file and includes from servers, the per-user
  `~/.gitconfig`, XDG and repository files, gitattributes driver activation,
  `includeIf` evaluation, built-in alias shadowing, startup-inventory and provenance
  wiring, UI, and AI classification of custom entries.
- **Compatibility:** none. The module is pure, has no callers and changes no schema,
  API, UI, authentication, scheduling or response authorization.

## 2026-11-26: increment 2, built-in collection of `/etc/gitconfig`

- **Delivered** (branch `claude/vibrant-tesla-w7wy0x`), mirroring the #1530 and #1390
  increment-2 pattern:
  - The agent's built-in startup scope (`target/agent.py` `PERSISTENCE_FILES`) now includes
    `/etc/gitconfig`. It is hashed as metadata only. A symlink is recorded, not followed,
    and nothing in it is parsed or run: no alias, pager, fsmonitor hook or include.
  - The path joins the reviewed `persistence.ADDITIVE_BUILTIN_SCOPE`. A baseline that an older
    agent collected stays comparable within its own scope. The file is listed as
    `newly_in_scope` and shown as `not_in_baseline`, not as `added`. Neighbouring paths such as
    `/etc/gitconfig.d`, `/etc/gitattributes` or `/etc/gitconfig.local` are not additive.
  - The path joins `PROMOTED_PERSISTENCE_FILES`. A saved monitor policy that already listed it
    as a custom path stays valid, and the file is covered once. Its parent `/etc` already
    overlapped built-in scope, so no custom path that was valid before becomes invalid.
  - Startup Files labels the file "System git configuration". The startup mechanism catalog
    gains a metadata-level, event-triggered, system-scope `git_system` mechanism. A coverage
    gap states that the commands the file can make git run are not parsed in this view yet,
    and that includes, per-user/XDG/repository files, `GIT_CONFIG_*` overrides and which
    accounts or jobs run git are not evaluated.
- **Acceptance:** `tests/test_gitconfig_scope.py` has 15 tests. Seven fail on main
  `e8ad2b90` and all pass on the branch. They cover agent hashing (including a symlink and
  `!` alias, `core.pager` and `core.fsmonitor` commands that must not run), additive
  comparison with and without the file present, a pre-anacrontab baseline that gains every
  promoted file together, real changes and removal once both inventories cover the file,
  non-additive neighbouring paths and downgrade, promoted custom paths, the catalog label and
  gap, the saved monitor policy API and the startup view.
- **Compatibility:** no schema, route, auth, scheduling or response-authorization change, and
  no file content is collected. Older agents keep working. Existing baselines list the file as
  newly in scope until a new baseline is approved.
- **Remaining for #1535:** feed the collected bytes to the `git_system_config` contract and show
  the parsed commands (needs bounded agent parsing or a content report with controller
  validation); collection of included files, per-user `~/.gitconfig`, XDG and repository
  files; gitattributes driver activation; package provenance; UI for parsed commands; and AI
  classification.
