# Retained native SQLite triage benchmark (#1609)

The [native capped SQLite workflow](https://github.com/StealthCat/MrPatchy/actions/runs/45891801549)
produced these captures on Ubuntu 24.04 with native `fcntl.flock` and SQLite
3.45.1. It benchmarked clean v1.110.0
`e8ad2b901c2becdb0de3379ffef3790c0953c690` using workflow commit
`bad7b14126146556d750c61196035321f205cab5`. The
[retained records](../benchmarks/ai-capped-v1110-sqlite-linux/) preserve the 12
raw captures, series output and runner provenance from the original artifact.
The replay test verifies each pair and the accepted comparison.

The six matched pairs alternated serial and four-slot run order. Every capture
completed eight investigations with four follow-ups, twelve loopback requests
and twelve synthetic settlements. No captures reported errors or approvals.
Four slots reduced median paired elapsed time by 58.8% and increased median
paired throughput by 142.8%. Parallel reconciliation p95 ranged from 3.231 to
13.165 ms, with a median paired increase of 5.587 ms. The native captures did
not reproduce the one-second Windows adapter delay.

The Windows records used SQLite 3.50.4 and a different operating system and
locking adapter. Compare serial and parallel within each series. Across
environments, the version and runner differences prevent attribution of the
timing change to a single factor. The fixture uses synthetic providers,
evidence delays and prices. Native MySQL and production-equivalent
performance acceptance remain open.
