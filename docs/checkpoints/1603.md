# Checkpoint: lighttpd command contract (#1603)

Roadmap F (startup and scheduled-task awareness), issue
[#1603](https://github.com/StealthCat/MrPatchy/issues/1603).

## 2026-11-26 — increment 1: pure contract

**Delivered** (branch `claude/magical-goodall-h11yty`): `app/lighttpd_commands.py`, a pure
contract that takes captured lighttpd configuration text, observed `include` glob matches,
optionally captured `include_shell` output, the service environment and captured
`/etc/passwd` and `/etc/group` text, and reports each command lighttpd 1.4.74 runs:

- `include_shell` commands, run while the configuration is parsed as the invoking user
  (root at service start, before `setuid`), with their output parsed as configuration;
- piped loggers (`server.errorlog`, `server.breakagelog`, `accesslog.filename` starting with
  `|`), including ones assigned inside `$HTTP[...]` conditionals, which start at daemon start
  as `server.username`/`server.groupname`;
- FastCGI and SCGI `bin-path` backends, executed directly with blank-split argv as
  `server.username`;
- the direct-versus-shell choice: a command of path characters only is executed directly; a
  blank, tab or `;` selects `$SHELL -c` (`/bin/sh` when unset);
- the configuration language: comments, `\"` escapes, integers, arrays with `=>`, `+`
  concatenation with key, `var.*` and `env.*` references (the stock
  `"/usr/share/lighttpd/use-ipv6.pl " + server.port`), `=` duplicate rejection, `:=` and
  `+=`, conditionals with `else`/`else $COND`, `global` blocks and relative `include` paths
  resolved against the including file.

Unobserved files or globs, uncaptured `include_shell` output, unresolved references, unknown
accounts, parse errors, include depth and size limits are blocking gaps; `complete` is false
when any is present. `origin` is `not_assessed` and `authorizes_response` is always false.

**Native evidence.** Ubuntu 24.04 `lighttpd 1.4.74-1ubuntu3` traced with
`strace -f -e trace=execve,setuid,setgid,setresuid`:

1. A mixed configuration (`include_shell` with concatenation, an included drop-in with its own
   `include_shell`, piped error/access loggers, a conditional access logger and a FastCGI
   `bin-path`): both `include_shell` commands ran as uid 0 before `setuid(33)`; the three
   loggers and the backend ran as uid/gid 33; the backend argv was blank-split without a shell.
2. `SHELL=/bin/bash` made `include_shell` and loggers use `/bin/bash -c`.
3. The stock Debian `lighttpd.conf` under `lighttpd -tt`: `create-mime.conf.pl` executed
   directly, `use-ipv6.pl 80` through `/bin/sh -c`.
4. Direct versus shell: `/srv/lt3/sh1` and `|/srv/lt3/lg` executed directly; a trailing tab or
   `;` used `/bin/sh -c`.
5. Relative `include` resolved against the including file's directory from two working
   directories; an empty glob was skipped; a missing plain include rejected the configuration.

`tests/test_lighttpd_commands.py` (20 tests) replays these runs and the rule edge cases.

**Remaining** (not in this increment): agent collection of `/etc/lighttpd` and
`include_shell` output, startup catalog/provenance integration, Startup Files UI, AI
classification, request-time `cgi.assign` interpreters, `mod_magnet` Lua scripts and the
exact lighttpd shell-metacharacter set beyond blank, tab and `;`.

## 2026-11-26 — review fix: effective assignments and global syslog

Stuck-PR fixer, addressing the
[changes-requested review](https://github.com/StealthCat/MrPatchy/pull/1604#issuecomment-7202007261)
on `2cb8eacb`:

- Startup rows now come from the effective value of each scope (global or one conditional),
  not from every assignment. A same-scope `:=` that replaces a piped logger with another pipe
  or with a normal file reports only the final destination. `+=` appends to the scope's own
  value, or to the inherited one, and each appended FastCGI/SCGI entry keeps the file and line
  that added it. A replacement inside a conditional does not hide the global logger.
- An enabled global `server.errorlog-use-syslog` skips the global `server.errorlog`, as
  `config_log_error_open` does in lighttpd 1.4.74; a non-blocking
  `errorlog_replaced_by_syslog` note records the skipped pipe. Conditional error logs are
  still reported. A value outside `enable`/`enabled`/`true`/`1`/`disable`/`disabled`/
  `false`/`0` or an integer is a blocking `unrecognized_boolean` gap, and the pipe is still
  reported.
- `include_shell` commands are still recorded at parse time, whatever later assignments do.

Four new regressions use inert command strings (24 tests in total); each fails on `2cb8eacb`.
The syslog rule follows the upstream source; it was not traced natively in this fix.

## 2026-11-27 — increment 2: collector capture

**Delivered** (branch `claude/vibrant-tesla-84jmx8`): agents hash the lighttpd configuration as
built-in startup scope. Nothing is parsed or run; the files are metadata and SHA-256 only, like the
other built-in startup files.

- Debian and RPM families: the `/etc/lighttpd` directory (built-in root). It holds `lighttpd.conf`
  (`DEFAULT_CONFIG` of `app/lighttpd_commands`), `conf-available`, the Debian `conf-enabled`
  symlinks (targets recorded, not followed), `modules.conf`/`conf.d` on RPM, and any certificates or
  keys stored there.
- `app/persistence.py`: the path is additive built-in scope. An earlier complete inventory still
  compares within its own scope and lists it as newly covered. Neighbouring paths
  (`/usr/share/lighttpd`, `/var/lib/lighttpd`, `/etc/lighttpd.bak` and similar) stay non-additive.
- A stored custom path equal to `/etc/lighttpd`, or a canonical path inside it, is promoted through
  the built-in directory mechanism from #1639, so saved monitor policies stay valid and are
  inventoried once. Non-canonical paths inside it are still rejected.
- Both startup catalogs label the path (`lighttpd`, trigger `boot`), with a gap saying the
  `include_shell`, piped-logger and FastCGI/SCGI `bin-path` commands are not yet parsed in this view.

**Validation:** 30 tests in `tests/test_lighttpd_scope.py`; 11 fail on main `640085f`. The
startup, persistence, scope and agent suites pass (652 tests). Ruff F checks, compileall and
`check_version --allow-unversioned` are clean.

**Compatibility:** additive built-in scope only. No schema, route, UI, auth, scheduling or

## 2026-11-27: increment 3, agent token reduction and Startup Files display

- **Delivered** (branch `claude/friendly-hopper-bd6x29`): agents reduce every regular `*.conf` file under `/etc/lighttpd`, from the exact hashed bytes, to the token stream `app/lighttpd_commands.py` reads. The lexer is a port of the contract's own lexer. Keys, references, operators, conditionals and integers are kept. Strings are kept only where the contract reads them: `include`/`include_shell` targets and conditional patterns, `var.*` values, `server.username`/`server.groupname`, the piped-logger and `server.errorlog-use-syslog` keys, keys the same file references, and FastCGI/SCGI extension and option names with their `bin-path` and `max-procs` values. Every other string becomes a valueless `drop` token. That covers socket paths, `bin-environment` values, `auth.backend.*` passwords, `mysql-vhost.pass` and `ssl.pemfile`. Kept strings use the best-effort cron credential redaction. A lexing gap (unterminated string, bad conditional, unexpected character) makes the file a single `error`/`char` token, because lighttpd rejects the configuration. Files over 1 MiB, not UTF-8 or with NUL bytes are `parsed: false`. More than 4,000 tokens, a string over 1,024 characters or a word over 256 characters sets `truncated`. Certificates, keys and symlinks are never parsed.
- **Controller:** `persistence.validate_lighttpd` strictly validates each report. It checks exact keys, the token kinds and their value shapes, non-decreasing lines (accounting for multi-line strings), that a `drop` token carries no value and matches the count, error placement and bounds, and that tokens come only from regular `/etc/lighttpd/**/*.conf` files. `persistence.metadata` strips the tokens, so comparisons and incident evidence are unchanged. `startup_inventory.lighttpd_text` rebuilds text that the contract tokenizes identically. `lighttpd_view` evaluates `/etc/lighttpd/lighttpd.conf` and resolves include globs iteratively. Absent paths, glob matches and symlinks to a reported file under `/etc/lighttpd` (Debian's `conf-enabled`) are observed only from a complete collection. A command that contains a value the agent did not retain gets a blocking `value_not_retained` gap. The service environment (root, `SHELL` unset, `/`) is stated as an assumption.
- **Startup Files:** `lighttpd.conf` shows each command's kind, key and extension, its command and argv, when it runs (while parsing, before the privilege drop, or at daemon start with the enclosing conditional), its account and its source line. A blocking-gap count and the gap list are shown. Other parsed files, older agents and unparsed files are explained. The Coverage catalog counts parsed files.
- **Validation:** `tests/test_lighttpd_tokens.py`: 1,200 seeded configurations, including broken ones, evaluate identically from raw and rebuilt text (commands, gaps, notes, files, accounts, fingerprint), and no rebuilt command contains the dropped marker. 300 lexer fuzz cases match the contract's lexer. Further cases cover secret dropping and redaction, lexing gaps and their lines, limits, 27 malformed-report rejections, the Debian layout through `conf-enabled` symlinks, an RPM layout with nested globs, incomplete/outside/link/directory cases, cross-file dropped values, older agents and an end-to-end agent run that executes nothing. `tests/ui_startup_lighttpd.cjs` checks escaping, timing, accounts, gaps and 320/768/1440 px layouts.
- **Review fix (privacy, review of `37ac1b4`):** a bare string is now kept only in a position the contract reads: an `include`/`include_shell` target expression, a conditional selector field (for a `$COND` that starts a statement) or a conditional pattern expression. Every other bare string is a `drop` token, including leftovers of a malformed drop-mode value (`mysql-vhost.pass = "a" "b"`, `mysql-vhost.pass "b"`, `auth.backend.plain.userfile = [ "b" ]`) in files lighttpd would reject. Backend key names are kept only to the option depth (3), so `bin-path`, `max-procs` and environment names nested in `bin-environment` are dropped. 13 new leak cases and a positive-position case fail or differ on `37ac1b4` and pass now; the 1,200-configuration differential still matches.
- **Known limit, follow-up:** Fedora's stock `lighttpd.conf` writes `conf_dir` for `var.conf_dir`. The contract resolves only the literal key, so those references produce a blocking `unresolved_reference` gap instead of a guess. lighttpd's documented prefix-less lookup should be confirmed natively and added to the contract.
- **Remaining for #1603:** capture of `include_shell` output, `/etc/passwd`/`/etc/group` capture for `server.username`, prefix-less `var.` references, package provenance and AI classification.
