# Parse distribution metadata once per scoring host snapshot

Update scoring and its administrator queue summary reused the RPM version
index but parsed OS release text again for each package identity. Scoring
also parsed it while constructing the provider payload and revalidating the
reply.

The worker and queue summary now retain the same parsed distribution and
package manager fields in their prepared host snapshots. Provider evidence
and exact identities use the same fields and values. Result revalidation
builds a separate snapshot from freshly read inventory, so a changed OS
version still supersedes the old scores. This does not alter admission,
provider configuration, evidence selection or queue order.

Five regression cases fail on main
`9b6a9d585dc6aca4ee81c2850feb287a8ccf0176`. The 11-update multipage
summary goes from 11 distribution parses to one. The five-update scoring
fixture goes from 16 to two, one before the request and one on fresh
revalidation. APT and RPM payloads and score IDs are unchanged, and changes
during the request still supersede the batch. This measures parser work,
with production throughput and independent scoring capacity still open.
