# Checkpoint: Dovecot service contract (#1620)

Roadmap F (startup and scheduled-task awareness). Issue
[#1620](https://github.com/StealthCat/MrPatchy/issues/1620).

## 2026-11-26 — increment 1: pure contract

**Delivered** (branch `claude/magical-goodall-vj7t3r`): `app/dovecot_services.py`, a pure contract. It
takes captured Dovecot configuration text, observed `!include` glob matches and `/etc/passwd` and
`/etc/group`. It reports every configured `service` whose executable differs from the package default,
with:

- the argv and the resolved program (`libexec_dir` for relative names);
- the `script`/`script-login` wrapper and the program it runs;
- the exec account and the account the program runs as;
- `master_start` (`process_min_avail` > 0) or `on_demand`;
- whether the service's protocol is enabled;
- the source file and line.

The key native finding: the master execs a non-Dovecot executable as **root** even with `user = nobody`,
unless `drop_priv_before_exec = yes`. Dovecot binaries, including the `script` wrapper, drop to the
service user after they start. The service user is reported anyway, with a non-blocking
`service_user_not_applied` note.

The parser rules match native `doveconf` 2.3.21:

- `#` outside quotes starts a comment anywhere on a line. It is removed before a trailing `\` is seen.
- An empty or comment-only line discards a pending continuation.
- A value is unquoted only when its first and last characters are the same quote character.
- `{` must end its line. Same-name services merge.
- `!include` with no match is fatal. `!include_try` with no match is skipped.
- `$protocols` expands to its earlier value. `$default_internal_user` and `$default_login_user` are resolved.
- The built-in service defaults are taken from `doveconf -a`.

Unobserved files or globs, `<file` values, malformed or unterminated sections, services inside filters,
unknown accounts, NUL bytes and over-limit input are blocking gaps. `origin` is `not_assessed` and
`authorizes_response` is always false.

**Validation:**

- 10 tests in `tests/test_dovecot_services.py` cover native runs on Ubuntu 24.04
  `dovecot-core 1:2.3.21+dfsg1-2ubuntu6.5`. `dovecot -F` was run with a recorder script that logged
  `id -u`/`id -g`/argv:
  - raw executables: uid 0, with or without `user`;
  - `drop_priv_before_exec = yes`: 65534:65534;
  - a `script` wrapper: 65534, with the client argument appended;
  - a service without `process_min_avail`: did not start.
- A seeded differential of 400 random service configurations agreed with native `doveconf -h`
  executable, user and `drop_priv_before_exec` on all 383 configurations doveconf accepted. On the 17
  it rejected, the contract was also not `complete`.
- Three targeted mutations each fail the tests: exec account, continuation discard and
  `!include_try` handling.
- `ruff check` is clean. `check_version --allow-unversioned` passes.

**Compatibility:** new files only. No schema, route, UI, auth, scheduling, agent or
response-authorization change.

## 2026-11-27 — increment 1 review correction: root exec versus unverified later drop

**Delivered** (branch `claude/magical-goodall-h9kz1x`, on top of the unchanged increment-1 commit
`4f7ba0e`). This addresses the
[Codex review](https://github.com/StealthCat/MrPatchy/pull/1621#issuecomment-7205906098) of #1621.
The draft inferred the program's account from the executable's directory: a path under `libexec_dir`
names a file, not its provenance.

- `program_account` is now verified only when `drop_priv_before_exec = yes`. The master then applies the
  restriction settings before exec (`program_account_basis: restricted_before_exec`).
- Every other service is exec'd as root. Its `program_account` is `None` (unknown), with basis
  `post_exec_drop_unverified` (or `post_login_switch_unverified` for `script-login`). A path under
  `libexec_dir` reports the expected later drop as `expected_drop_account` only. A non-blocking
  `post_exec_account_unverified` gap is recorded when the service user is not root.
- `root_programs` is replaced by `root_exec`, every enabled service exec'd as root, whatever its expected
  later drop. `unverified_program_accounts` lists the enabled services whose post-exec account is unknown.
- The fingerprint covers the basis and the expected drop account.

**Validation:** 11 tests pass (one new test: libexec path, root-user `drop_priv`, and a dropped
`script` wrapper). Three mutations each fail the tests: crediting a libexec path with the service
account, deriving `root_exec` from the unknown account, and leaving the new fields out of the
fingerprint. `ruff check` is clean.

**Remaining under #1620:**

- agent collection of the configuration;
- Startup Files display and package provenance;
- AI classification;
- checkpassword passdb/userdb programs, `quota_warning` and sieve extprograms;
- a native trace of the `script-login` post-login account, which is source-derived.

## 2026-11-27 — increment 2: collector capture

**Delivered** (branch `claude/magical-goodall-tjey2x`, on main `e84295b`, v1.121.0): agents hash the
Dovecot configuration directory `/etc/dovecot` as built-in startup scope. Nothing is parsed or run.
Files are metadata and SHA-256 only, like the other built-in startup files, and symlinks (such as
Ubuntu's `private/dovecot.pem`) record their target without being followed.

- `/etc/dovecot` is the configuration root on both the Debian and RPM families. It holds `dovecot.conf`,
  `conf.d` and any other files administrators keep there, including passdb/userdb files and TLS keys.
  Only their metadata and digest are recorded; no content leaves the host.
- `app/persistence.py`: the directory is additive built-in scope. An earlier complete inventory still
  compares within its own scope and lists it as newly covered.
- A stored custom path equal to or inside `/etc/dovecot` is promoted through `PROMOTED_PERSISTENCE_ROOTS`
  (#1639's mechanism), so saved monitor policies stay valid and the files are inventoried once. A stored
  `/etc/dovecot` stays in scope and keeps comparing. A stored file or directory inside it is listed as
  `previously_custom` and keeps comparing. Siblings such as `/etc/dovecot.bak`,
  `/usr/share/dovecot/protocols.d` and `/etc/pki/dovecot` stay ordinary additional scope.
- `app/startup_inventory.py` labels the directory and states the parsing gap. `app/startup_catalog.py`
  adds the `dovecot` event mechanism for both families.

**Validation:** `tests/test_dovecot_scope.py` (30 cases) fails 11 of them on main `e84295b` and passes
with the change. The startup, persistence and agent suites pass. CI ruff selections and
`check_version --allow-unversioned` pass.

**Compatibility:** no schema, route, UI, auth, scheduling or response-authorization change. Agents add
about 20–40 entries on a host with stock Dovecot installed, within the existing 256-entry inventory
budget.

**Next increment:** agent-side parsing of the hashed configuration through `app/dovecot_services.py`
(include resolution within the captured directory, `/usr/share/dovecot/protocols.d` as a reported gap
or a separate captured path) and the Startup Files display.

## 2026-11-27 — increment 3: agent statements and Startup Files evaluation

**Delivered** (branch `claude/magical-goodall-lao15q`). Agents now parse what they already hash.

- **Agent** (`target/agent.py`, `parse_dovecot`): when job parsing is on, the agent parses every regular
  file under `/etc/dovecot`, from the exact hashed bytes. It ports the contract's 2.3.21 lexing (comments
  outside quotes, continuation and its blank-line discard, quoting, `!include`/`!include_try`, section and
  assignment classification). The output is a statement stream of `include`, `open`, `close`, `set` and
  `error` statements, each with its first line number. Only these values are kept:
  - section kinds and names;
  - include patterns;
  - the global and service keys the contract reads (`protocols`, `default_*_user`, `libexec_dir`,
    `executable`, `user`, `group`, `drop_priv_before_exec`, `process_min_avail`, `protocol`, `chroot`).

  Every other value is dropped and counted, including passwords, SQL connect strings and key material.
  `<file` values keep only that fact. Executables get the cron credential redaction. Rejected lines keep
  only their line number. Files over 1 MiB or with NUL bytes are not parsed. A file over 2,000 statements
  is truncated. Symlinks are not followed or parsed. Nothing is executed.
- **Controller** (`app/persistence.py`, `validate_dovecot`): validates each report strictly, with exact
  key sets per statement kind, increasing lines, bounded single-line text and kept values only for
  contract keys. Redaction applies only to `executable`. Reports are accepted only on regular files under
  `/etc/dovecot`. Parsed detail is excluded from baseline comparison.
- **View** (`app/startup_inventory.py`, `dovecot_view`): rebuilds equivalent configuration text, with
  each statement on its original line, and runs `app/dovecot_services.evaluate` from `dovecot.conf`.
  - Absent paths and in-directory glob matches count as observed only when the stored inventory is a
    complete collection. Glob matches skip dot-names, and a glob that matches a subdirectory is left
    unobserved.
  - Unreported, unparsed, truncated and symlinked files stay unobserved, and so do includes outside
    `/etc/dovecot`. Any of these blocks the evaluation.
  - `/etc/passwd` and `/etc/group` are not captured, which is a blocking gap.
  - The view is never `complete` and never authorizes a response.
- **UI** (`startupDovecot`): the `dovecot.conf` row lists each non-default service with its executable,
  starting account (root unless dropped before exec, plus any expected drop marked not verified),
  timing, protocol enablement, source line and coverage gaps. A refused evaluation shows a warning
  instead of guessing. Other files show their parsed statement count, older-agent state or unparsed
  state. The catalog label counts parsed files.

**Known limit:** stock Ubuntu `dovecot.conf` includes `/usr/share/dovecot/protocols.d/*.protocol`, which
is outside the inventory scope, so the view refuses the evaluation there. It names that blocking gap
rather than assuming the protocols. **Next increment:** capture that directory (and passwd/group
accounts) so stock configurations can be evaluated, then provenance and AI classification.

**Validation:** `tests/test_dovecot_statements.py` has 28 tests:

- rebuilt text evaluates identically to the captured text;
- a seeded differential of 600 configurations (342 accepted, 218 with services) matches the contract
  exactly;
- secrets are dropped;
- 14 malformed-report rejections;
- complete, incomplete, outside-directory, older-agent and truncated coverage;
- an agent end-to-end run that executes nothing.

Three agent mutations each fail the tests: the continuation discard, comment stripping, and parsing
only regular files. The Dovecot, startup, persistence, request-key and autofs suites pass (354 tests).
`tests/ui_startup_dovecot.cjs` passes against a live server, with no horizontal page scroll at
320/768/1440 and escaped untrusted text.
