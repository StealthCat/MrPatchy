# Update-scoring queue summary working set (#1588)

## 2026-11-26

- Roadmap A follow-up to #917 and #436. The read-only status route computes
  each exact identity once using its retained per-host version index and
  keeps the earliest retry or deferral deadline as it passes each page.
  It leaves the scheduler memo and persisted scores alone.
- On v1.110.0 the focused regression observed a per-update memo insertion
  in the live queue summary. A multi-page fixture preserves counts and
  the earliest deadline. The worker tests cover pause, exact identity,
  retry, administrator-only access and redaction.
- A disposable SQLite fixture with 6,000 deferred updates over 12 hosts
  returned identical counts and timestamps with 63 SQL statements on both
  versions. Median peak traced Python allocations over three warm runs
  dropped from 3,706,880 to 1,218,846 bytes.
- Traced Python allocations do not measure process memory, database
  buffers or production throughput. Each status request still walks the
  current candidate fleet and retains one version index per host.
