# Read the triage candidate and server lifecycle together

[#1575](https://github.com/StealthCat/MrPatchy/issues/1575) is a Roadmap A admission increment. The worker rereads the elected behavior and its server lifecycle together after acquiring the existing queue lock and opening a fresh database snapshot. This removes one database round trip while the admission lock is held. The lookup also requires the behavior to still belong to the server protected by the queue lock.

The regression records two rereads on v1.108.0 and checks that one projected lookup supplies fresh behavior evidence and only server lifecycle fields. Approval, verdict and lifecycle checks still apply. Retained behavior rows without a server record continue to work. Provider, response authorization, schema and UI behavior are unchanged.
