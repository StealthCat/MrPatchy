# Checkpoint: ISC dhcpd execute() contract (#1593)

Roadmap F (startup and scheduled-task awareness), issue
[#1593](https://github.com/StealthCat/MrPatchy/issues/1593).

## 2026-11-26 — increment 1: pure contract

**Delivered** (branch `claude/vibrant-tesla-gsaxlm`): `app/dhcpd_execute.py`, a pure contract
that takes the file record for `/etc/dhcp/dhcpd.conf` and the observed dhcpd command line and
reports which `execute()` programs ISC dhcpd 4.4.3-P1 runs, on which event, in which scope,
under which conditions and as which user:

- `conflex.c` tokenizing: `#` comments, quoted strings with `\t \r \n \b`, octal and hex
  escapes, case-insensitive keywords, the 1500-byte token buffer. An escaped NUL truncates the
  program, as `strcpy` does.
- `execute("program", expr, ...)`: the program must be a quoted string or the configuration is
  rejected; it runs through `fork`/`execvp` (PATH search when it has no `/`, no shell) and dhcpd
  waits for it. Literal arguments give a full argv; expression arguments are reported as source.
- `on commit|release|expiry|transmission` joined by `or`. A later `on` for the same event
  replaces the earlier one; scopes run outermost to innermost (subnet/shared-network and pool,
  then matching classes, then host), so inner and later `on` statements are reported as
  `replaced_in_same_scope` / `replaced_events` / `may_be_replaced_by`.
- `if`/`elsif`/`else if`/`else` and `switch` conditions are carried with each program.
- **Global-scope `execute()` outside `on` runs as root** at every start and every `dhcpd -t`
  (`postconf_initialization` runs before the config-test exit and before `-user` drops
  privileges), then as the process user for each packet. Subnet-level statements run per packet
  only.
- Process user from `-user`/`-group` (root when absent); an unobserved command line assumes the
  packaged unit (`-user dhcpd -group dhcpd`) with a non-blocking gap.

`include`, nested `on`, `execute()` in data blocks, unbalanced braces, unterminated strings,
over-limit input, NUL bytes, invalid UTF-8 and unobserved/unknown files are named gaps; a
blocking gap makes the result incomplete. Rejected configurations mark every program
`runs_only_if_config_accepted`.

**Validation:** 18 tests in `tests/test_dhcpd_execute.py`. Eight reproduce native runs of
isc-dhcp-server 4.4.3-P1-4ubuntu2 on Ubuntu 24.04 (dhcpd in one network namespace with the
packaged unit's arguments, dhclient in another over a veth pair, `strace -f -e trace=execve`,
and `dhcpd -t`): root-then-dhcpd global scope runs, last/innermost `on commit` winning, a class
replacing a global commit but not its release, per-packet subnet scope, lease expiry, execvp
PATH search, else-if branches, case-insensitive keywords, NUL truncation and four rejected
configurations.

**Compatibility:** new files only. No schema, route, UI, auth, scheduling, agent or
response-authorization change.

**Remaining under #1593:** agent collection of `/etc/dhcp/dhcpd.conf` (and the
`/etc/default/isc-dhcp-server` command-line inputs), `include` following, DHCPv6
(`dhcpd6.conf`) timing, startup catalog and provenance integration, UI and AI classification.

## 2026-11-28 — increment 2: built-in startup scope

**Delivered** (branch `claude/vibrant-tesla-f30mi3`): agents hash `/etc/dhcp/dhcpd.conf`,
`/etc/dhcp/dhcpd6.conf` and the Debian-family `/etc/default/isc-dhcp-server` command-line
defaults as metadata-only built-in startup files on both families. Nothing in them is parsed or
run, and no file content (such as TSIG or OMAPI key secrets in `dhcpd.conf`) is stored.

- Neither `/etc/dhcp` (dhclient hooks and leases) nor `/etc/default` (every package's
  defaults) is built-in. The three files are nested built-in files, as #1599 did for
  `/etc/lvm`: a custom `/etc/dhcp` or `/etc/default` saved earlier stays valid, and its
  traversal leaves these files to built-in scope so each is inventoried once. A saved custom
  path equal to one of the files is promoted.
- The paths are additive to earlier baselines. A file inside an earlier custom directory keeps
  comparing; others are listed as newly covered.
- Both startup catalogs label the files (`dhcpd`, `dhcpd6`, `dhcpd_defaults`). A coverage gap
  says the `execute()` programs are not yet evaluated in this view, and names what is not
  observed: `include` targets, the rest of `/etc/dhcp`, `/etc/ltsp/dhcpd.conf`, the RPM-family
  `/etc/sysconfig/dhcpd` and `-cf`.

**Validation:** 28 tests in `tests/test_dhcpd_scope.py` (scope tuples, real agent hashing with
a planted `execute()` marker that never runs and a secret that is never stored, absent files,
saved custom paths, overlap rejection, nested traversal, baseline comparison, promotion,
catalog labels and the startup-inventory API). `tests/test_lvm_scope.py` now checks only the
LVM entries of the shared nested-file tuple. 44 related test modules (1,329 tests) pass.

**Compatibility:** additive scope only. No schema, route, auth, scheduling or
response-authorization change.

**Remaining under #1593:** agent parsing of the hashed bytes with the increment 1 contract,
the Startup Files view of the programs and accounts, `include` following, DHCPv6 timing,
provenance and AI classification.
