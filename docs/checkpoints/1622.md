# Retained native MySQL triage benchmark (#1622)

The [native benchmark workflow](https://github.com/StealthCat/MrPatchy/actions/runs/45909360289)
produced these captures on Ubuntu 24.04 with a disposable MySQL 8.4.13 service.
It benchmarked clean v1.112.0 `20c950d5bbbfce78aa8cbf42b36712d62ca68b5c`
using workflow commit `a3a2349c08b416469f339ed5b8a66536987dfaef`. The
[retained records](../benchmarks/ai-capped-v1112-mysql-linux/) preserve the
12 raw captures, accepted series and runner provenance from the
[original artifact](https://github.com/StealthCat/MrPatchy/actions/runs/45909360289/artifacts/15158948428).

The six matched pairs alternated serial and four-slot run order. Each capture
completed eight investigations with four follow-ups and settled 12 synthetic
charges, with zero approved subjects and zero errors. Four slots reduced
median paired elapsed time by 53.4% and increased median paired throughput by
114.5%. Median paired reservation p95 increased by 30.846 ms and reconciliation
p95 by 25.003 ms. The replay tests verify the original series, including its
ledger timing summary, and keep the separate native SQLite coverage.

The same workflow also ran SQLite on a separate hosted runner. Compare
serial and parallel within each backend first. Differences between runners
limit comparisons of absolute timings across backends. This evidence covers
a disposable local database, a loopback provider and synthetic prices.
Production throughput, remote database latency and broader scoring
performance acceptance remain open.
