# Checkpoint: runit service-directory contract (#1628)

Roadmap F (startup and scheduled-task awareness), also feeding roadmap E. Issue
[#1628](https://github.com/StealthCat/MrPatchy/issues/1628).

## 2026-11-27 — increment 1: pure contract

**Delivered** (branch `claude/magical-goodall-qyvex9`): `app/runit_services.py`, a pure contract. It takes
captured metadata for the directory a running `runsvdir` scans, plus the observed `runsvdir` process, and
reports which programs runit 2.1.2 runs for each supervised service:

- Scan rules: names starting with `.` are skipped, `stat` follows symlinks, only directories get `runsv NAME`,
  a dangling symlink is skipped, and at most 1000 services are supervised (later ones depend on `readdir`
  order, which is a blocking gap).
- `./run` is run with `execve("./run", ["./run"])` (no shell or `PATH` fallback) and retried about once a
  second. `down` of any type holds the service down until `sv up`/`sv once`; a dangling `down` symlink does not.
- `./finish EXITCODE SIGNAL` runs after every exit or failed start of `./run` whenever `finish` can be opened.
- `log/run` runs when `log` is a directory, unless `log/down` exists. `log/finish` and `log/control` are never
  run.
- `control/C` for `u d x t k p c a h i q 1 2` needs the owner execute bit. `control/u` runs before every start
  attempt and is automatic. The other letters need an `sv` command or shutdown.
- Each program has its argv, working directory, event, `automatic` flag, exec account (`runsvdir`'s account)
  and an unknown final account, because a run script's own privilege drop (for example `chpst -u`) is in
  script contents, which are not read.

An unobserved supervisor, directory, service or control metadata, a special file, a scan-directory mismatch (which also leaves automatic execution and the exec account unknown),
a truncated listing and over-limit input are blocking gaps. A result with any blocking gap is not `complete`.
`origin` is `not_assessed` and `authorizes_response` is always false.

**Validation:** 19 tests in `tests/test_runit_services.py`. The native cases come from Ubuntu 24.04
`runit 2.1.2-59ubuntu1`, traced with strace (`execve`). An optional native differential test runs a real
`runsvdir` (when installed, as root) on 14 entries and checks that the programs that ran are exactly
`automatic_programs`. It first caught a wanted-down service's `./run` being reported as automatic, and it
confirmed that `./finish` runs when `./run` cannot be executed. Five targeted mutations each fail the tests.

**Compatibility:** new files only. No schema, route, UI, auth, scheduling, agent or response-authorization
change.

**Remaining under #1628:** agent collection, Startup Files display, package provenance against `/etc/sv`, boot
enablement (`runit.service` or runit as PID 1), the environment `runsvdir` passes on, and AI classification.

## 2026-11-27 — increment 2: built-in startup scope

**Delivered** (branch `claude/vibrant-tesla-xgcvtj`): agents hash runit's service directories as built-in startup
scope, as metadata and SHA-256 only, using the Ubuntu 24.04 `runit 2.1.2-59ubuntu1` package layout:

- `/etc/sv` (service definitions: `run`, `finish`, `log/run`, `down`, `control/*`; `supervise` symlinks into
  `/run/runit` are recorded, not followed) and `/etc/runit` (stage scripts `1`, `2`, `3`, `ctrlaltdel` and the
  `runsvdir/<level>/` directories of service links, including the `current` link) are walked as roots.
- `/etc/service` is a root that may itself be a symlink (`SYMLINK_RECORDED_ROOTS`): on Debian and Ubuntu it is
  `runit/runsvdir/current`, which is recorded as one symlink entry and never followed. Where it is a directory,
  it is walked as usual. Every other built-in root that is a symlink is still a gap.
- FIFOs and other special files (for example in a `supervise` directory that is not a symlink) are disclosed as
  excluded entries and never opened.
- The three paths are additive to earlier baselines (`ADDITIVE_BUILTIN_SCOPE`) and promote saved custom paths
  inside them. Both catalogs label them (`runit`, `runit_stages`, `runit_sv`) with a coverage gap.

**Bundled bug fix (#1666, P2):** the controller rejected any inventory with more than 32 scope paths. With
built-in scope at 25 on main (28 with this increment), 8 or more saved custom paths made every comparison and
the startup view fail. The bound is now `persistence.MAX_SCOPE = 64` (built-in scope plus 16 custom paths).

**Validation:** 35 tests in `tests/test_runit_scope.py`. The full-custom-scope regression fails against main's
validator and passes with the fix.

**Compatibility:** additive scope only. No schema, route, UI, auth, scheduling or response-authorization change.
Older agents keep their earlier scope, and older baselines compare within their scope.

**Remaining under #1628:** agent-side parsing of service directory metadata into the #1628 contract input, Startup
Files display, package provenance, boot enablement (`runit.service` or runit as PID 1), the environment
`runsvdir` passes on, and AI classification.
