# #837 — SHELL and PATH for each parsed cron job (roadmap F)

## 2026-11-26 — acceptance criterion 3 (Startup Files UI)

- **Roadmap item:** F, startup and scheduled-task awareness. Criteria 1, 2 and 4
  (agent `parse_cron` reporting, controller validation and regression tests) shipped in
  #838 (v1.75.28). This change delivers criterion 3, the last one.
- **Delivered:** the Startup Files cron job table has a "Shell and PATH set by this file"
  column. It shows the escaped `SHELL` and `PATH` the crontab assigns above each job,
  "cron default, not evaluated" when the file sets none, "set empty" for an empty
  assignment, a Truncated note for bounded values, and "Not reported by this agent
  version" for jobs from older agents. The environment note now says only SHELL and
  PATH values are shown. The coverage gap no longer says PATH/SHELL are unevaluated.
  It now says what is still not evaluated: cron daemon defaults, `/etc/environment`,
  PAM-supplied environment, how the shell resolves the command, and whether cron runs.
- **Boundaries:** presentation and gap text only. No agent, schema, validation, search,
  baseline comparison, authentication, scheduling or response-authorization change.
  Values are displayed as reported; nothing is executed or resolved.
- **Validation:** `tests/ui_startup_pages.cjs` fails on main (missing column) and passes
  with this change, including an injection attempt in PATH, at 320/768/1440 px with no
  horizontal page scroll. The gap regression in `tests/test_startup_inventory.py` fails
  on main and passes. Related cron/anacron/at/startup suites pass (162 tests).
- **Remaining:** none for #837. PATH-based command resolution and daemon defaults remain
  documented roadmap F gaps.
