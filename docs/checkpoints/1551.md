# Checkpoint: collectd exec-plugin contract (#1551)

Roadmap F (startup and scheduled-task awareness), issue
[#1551](https://github.com/StealthCat/MrPatchy/issues/1551).

## 2026-11-26 — increment 1: pure contract

**Delivered** (branch `claude/vibrant-tesla-gupwnq`): `app/collectd_exec.py`, a pure contract
that takes captured `collectd.conf` text, captured `Include` targets (files and directory
listings) and captured `/etc/passwd` and `/etc/group` text, and reports each program
collectd 5.12.0's `exec` plugin starts:

- `Exec` programs (started at every read interval while not running) and `NotificationExec`
  programs (started per notification), with the source file and line;
- argv as the plugin builds it: basename argv[0], `%lf` numbers (`0755` is 755 because
  `strtod` reads it), lower-case-only booleans, and `PATH` search when the program has no `/`;
- the account: `getpwnam` uid and primary gid, the configured group as effective and
  supplementary gid, refusal of unknown users and of every uid 0 account, and the logged but
  ignored unknown group. A configured `root` group gives the program gid 0, and such
  programs are listed in `root_group_programs`;
- liboconfig scanning and parsing (longest-match tokens, echoed stray bytes, continuation
  lines, multi-line quoted strings, mandatory final newline, case-sensitive block close);
- `Include` expansion (top level only, `wordexp(WRDE_NOCMD)`, `strcmp`-sorted directories,
  basename `Filter`, depth 8) and which failures skip a drop-in versus reject the whole
  configuration;
- dispatch order: a `<Plugin exec>` block before `LoadPlugin exec` is ignored unless
  `AutoLoadPlugin` was set true earlier.

Unobserved files or listings, unsupported `wordexp` input (variables, quotes, `~`,
whitespace, relative paths, globs above the last component), a relocated `PluginDir`,
missing account databases and a non-root daemon are blocking gaps; a result with any gap is
not `complete`. `origin` is `not_assessed` and `authorizes_response` is always false.

**Validation:** 18 tests in `tests/test_collectd_exec.py`. Nine replay native runs of Ubuntu
24.04 `collectd-core 5.12.0-17.1build2` (`collectd -f -C` as root, traced with
`strace -f -e trace=execve,setgroups,setgid,setuid`): argv formatting and account handling
(`setgroups(2, [65534, 1])`, `setgroups(1, [65534])` for an unknown group,
`setgroups(2, [1, 0])` for `daemon:root`, the root refusal, the unknown user), the missing
final newline, the unquoted path, the case-mismatched block close, a block before
`LoadPlugin` with echoed bytes and a multi-line string, `AutoLoadPlugin` with an `Include`
inside the block, directory/glob/missing includes with a skipped broken drop-in, a direct
include not matching its `Filter`, and a direct include that fails to parse. The depth limit
(`l7.conf` not included), the `wordexp` failure on `;`, the empty configuration and an
unmatched glob were also checked natively.

**Compatibility:** new files only. No schema, route, UI, auth, scheduling, agent or
response-authorization change.

**Remaining under #1551:** agent collection of `collectd.conf`, its includes and listings,
startup catalog and provenance integration, UI, AI classification of the reported programs,
and the python/perl plugin module loading (`Import`, `LoadPlugin` of Perl modules), which
runs code inside the root daemon and needs its own slice.

## 2026-11-28 — increment 2: built-in startup scope

**Delivered** (branch `claude/magical-goodall-gzcrp8`): agents hash the Debian-family
`/etc/collectd` directory (`collectd.conf`, `collectd.conf.d`, `collection.conf`,
`filters.conf`, `thresholds.conf`), the RPM-family `/etc/collectd.conf` and the
`/etc/collectd.d` directory as metadata-only built-in startup scope on both families. Nothing in
them is parsed or run, and no file content (such as network plugin passwords) is stored.

- The paths are additive to earlier baselines. A saved custom path equal to or inside one of
  them is promoted, so saved monitor policies stay valid and each file is inventoried once.
  An earlier custom file inside the new scope keeps comparing; the others are listed as newly
  covered. Neighbouring paths (`/etc/collectd-web.conf`, `/etc/collectdmon.conf`,
  `/etc/collectd.conf.rpmnew`) are not promoted and stay non-additive.
- Both startup catalogs label the paths (`collectd`, `collectd_rpm`, `collectd_d`). A coverage
  gap says the `Exec`/`NotificationExec` programs are not yet evaluated in this view and names
  what is not observed: `Include` targets outside these paths, `-C`, and python/perl modules.

**Validation:** 36 tests in `tests/test_collectd_scope.py` (scope tuples, real agent hashing
with planted `Exec`/`NotificationExec` markers that never run and a password that is never
stored, both layouts, symlinked drop-ins, baseline comparison, promotion, overlap and
non-canonical rejection, neighbouring paths, catalog labels and the startup-inventory and
monitor-policy APIs). 16 of them fail on main `8d13a56` and all pass with the change.

**Compatibility:** additive scope only. No schema, route, auth, scheduling or
response-authorization change. The scope tuples are also extended by in-flight #1699 (dhcpd)
and #1704 (syslog-ng); the resulting conflicts are additive list merges.

**Remaining under #1551:** agent parsing of the hashed bytes with the increment 1 contract
(including `Include` resolution and `/etc/passwd`/`/etc/group` accounts), the Startup Files
view of the programs and accounts, provenance, AI classification and python/perl module
loading.

## Increment 3: agent-parsed items and the Startup Files view

**Delivered** (branch `claude/magical-goodall-22vm1e`): agents parse every regular file under
`/etc/collectd`, `/etc/collectd.conf` and `/etc/collectd.d` from the exact hashed bytes with a
Python 3.8 port of the increment 1 liboconfig scanner and parser (`parse_collectd`). Nothing is run
and no Include is opened. Only top-level `Include` (with `Filter`), `LoadPlugin`, `AutoLoadPlugin`
and `PluginDir` items and `<Plugin exec>` blocks keep values; `Exec`/`NotificationExec` arguments
after the program get the cron-command credential redaction. Every other item, including network
plugin passwords, is dropped and counted. Parse errors keep only their line and reason.

- `app/collectd_exec.evaluate` gains an additive `parsed` input (items or `ParseError` per path).
- `app/persistence.validate_collectd` rejects shapes agents never produce; `metadata()` excludes
  `collectd`.
- `app/startup_inventory.collectd_view` evaluates `/etc/collectd/collectd.conf` and
  `/etc/collectd.conf`. Directory listings and absent Include targets come only from a complete
  collection; symlinked, non-UTF-8, truncated and unreported files stay unobserved. `/etc/passwd`
  and `/etc/group` are not captured, so accounts are shown by name and `starts` is not assessed.
- `app/static/server.js` `startupCollectd`; catalog label `· N parsed files`.

**Validation:** `tests/test_collectd_agent_view.py` (17 tests) compares agent items plus the view
with the contract run on full text over the packaged config, native cases and 1500 seeded random
configs (CRLF, multi-line quotes, IPv4/IPv6, numbers, case-mismatched blocks, nested includes).
`tests/ui_startup_collectd.cjs` checks escaping, rejected/parse-error/older-agent states and no
horizontal scroll at 320, 768 and 1440 px.

**Remaining under #1551:** capturing `/etc/passwd` and `/etc/group` (uid/gid, root and unknown-user
refusal), Include targets outside these paths, `-C`, provenance, AI classification and python/perl
module loading.
