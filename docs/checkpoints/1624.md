# #1624: strongSwan swanctl updown contract

Roadmap F (startup and scheduled-task awareness), strongSwan slice.

## 2026-11-27: increment 1, pure contract

- **Delivered:** `app/strongswan_updown.py` (`evaluate(files=..., directories=..., config_path=..., charon_uid=...)`) and `tests/test_strongswan_updown.py`. For each swanctl connection and child, it reports the `updown` command, the exact argv (`/bin/sh -c "2>&1 <command>"`), the account, the source file and line, any shell metacharacters, and whether swanctl discards the whole connection. New files only.
- **Grammar (strongSwan 5.9.13):**
  - Sections with the same name merge, and the last value wins, including a value from a later include.
  - Unquoted words and double-quoted strings join with single spaces. Quotes are consumed, and the escapes `\" \\ \n \t \r` apply.
  - `#` starts a comment, `,` and `;` are literal, and a value ends at a newline or `}`.
  - `include` is relative to the including file's directory. Glob matches load in sorted order, hidden names are skipped, and a pattern with no match includes nothing.
  - A value containing a newline makes swanctl discard the whole connection.
- **Blocking gaps:** `complete` is false whenever one of these is present:
  - an unobserved file or directory listing;
  - an unsupported include pattern (a glob in a directory component, or a backslash);
  - an unknown escape, an unterminated quote, unbalanced braces or a syntax error;
  - a NUL byte;
  - over-limit text, files, include depth or commands;
  - a non-root daemon, or an invalid daemon uid. An invalid uid is now reported as `None`, never as root.
- **Not assessed:** whether the connection's other settings load, whether tunnels come up, and whether `strongswan.conf` disables the updown plugin. These are recorded as notes. `origin` is `not_assessed` and `authorizes_response` is false.
- **Native evidence:** Ubuntu 24.04 `charon-systemd`/`strongswan-swanctl 5.9.13-2ubuntu4.24.04.5`.
  - The earlier queued run established real CHILD_SAs between two namespaced daemons with `kernel-libipsec`, and the updown script recorded its uid, its parent's command line and its argv. Those cases are in `NativeRunTest`.
  - This run captured the `updown` values that native `swanctl --load-conns` sent in its vici `load-conn` request, using a stub socket. All 11 values matched the module. The cases covered word joining, a `,` literal, fully quoted shell quoting, `;` commands, last value wins, section merging, sorted include override, a skipped hidden file, a `\t` escape with `$HOME`, a value ending at `}` and a no-match include. Native swanctl also rejected a multi-line value with "invalid value for: updown, config discarded". The cases not already covered are in `NativeLoadConnTest`.
- **Validation:** 15 tests pass. 5 of 6 targeted mutations were caught at first: include sort order, the `\t` escape, connection discard, NUL bytes and the invalid-uid fallback. The hidden-file skip survived, so a `complete` assertion was added, and it now fails under that mutation. The startup test selection passes (164 tests), `ruff` is clean, and `check_version --allow-unversioned` passes against main `256a200`.
- **Remaining for #1624:** legacy `ipsec.conf` `leftupdown`/`leftfirewall`, `strongswan.conf` updown plugin enablement, built-in collection of `/etc/swanctl`, a startup-catalog entry and UI display.

## 2026-11-27: increment 2, collector capture

- **Delivered** (branch `claude/magical-goodall-h7ru3q`): agents hash the swanctl configuration as built-in startup scope, as metadata and SHA-256 only. Nothing in it is parsed or run, and symlinks are recorded without being followed. Two directories are covered:
  - the Debian-family `/etc/swanctl` directory (`swanctl.conf`, `conf.d`, and the `x509`, `private` and other credential directories);
  - the RPM-family `/etc/strongswan` directory (`swanctl/`, `strongswan.conf` and `strongswan.d`).
- **Baselines:** both paths are in `ADDITIVE_BUILTIN_SCOPE`, so an earlier baseline still compares within its own scope and lists them as newly covered. A downgrade or any other new path still makes the comparison unavailable.
- **Saved policies:** stored custom paths equal to or inside either directory are promoted through `PROMOTED_PERSISTENCE_ROOTS` and inventoried once. Neighbouring paths such as `/etc/strongswan.conf`, `/etc/strongswan.d` and `/etc/swanctl.bak` remain additional scope.
- **Catalogs:** Startup Files labels `/etc/swanctl` as "strongSwan swanctl configuration" and `/etc/strongswan` as "strongSwan configuration". The startup catalog has a `strongswan` mechanism with family-specific locations. A coverage gap says the updown commands are not yet parsed in this view. It also says the Debian-family `/etc/strongswan.conf` and `/etc/strongswan.d` (which can disable the updown plugin), legacy `ipsec.conf` `leftupdown`/`leftfirewall`, `swanctl --file` and other vici clients are not evaluated.
- **Validation:** `tests/test_strongswan_scope.py` has 39 cases. 15 fail without the source change. They cover a Debian and an RPM-layout tree with an executable updown script and a private key, which is hashed but never read into the report, plus a symlinked certificate. Startup, scope, persistence, ClamAV, Dovecot, request-key and strongSwan suites: 792 passed, 40 skipped. `ruff`, compileall and `check_version --base-ref 5c4402e --allow-unversioned` are clean.
- **Compatibility:** no schema, route, UI script, auth, scheduling or response-authorization change. Older agents keep working. Their reports simply have no entries under these paths.
- **Remaining for #1624:** agent parsing of the hashed swanctl bytes through `app/strongswan_updown.py`, plus a Startup Files display; legacy `ipsec.conf`; `strongswan.conf` updown plugin enablement; provenance; AI classification.

## 2026-11-27: increment 3, agent parsing and Startup Files display

- **Delivered** (branch `claude/vibrant-tesla-24bpsh`): agents reduce every regular `*.conf` file under `/etc/swanctl` and `/etc/strongswan/swanctl`, from the exact hashed bytes, to a statement stream (`open`, `close`, `include`, `set`, `error`). The agent ports the contract's strongSwan 5.9.13 lexer and statement rules. Section names, include patterns and setting names are kept. Only `updown` values keep their text, with the best-effort cron credential redaction. Every other value, including `secrets {}` PSKs, is dropped. Lexing gaps (unterminated quote, unknown escape) make the file a single `error` statement, as strongSwan ignores the whole file. A syntax gap ends the stream. Files over 1 MiB, not UTF-8 or with NUL bytes are `parsed: false`. Over-limit names (1,024), commands (512) or statement counts (2,000) set `truncated`. Key files, certificates, `strongswan.conf` and symlinks are never parsed.
- **Controller:** `persistence.validate_swanctl` strictly validates each report: exact keys per op, non-decreasing lines, no retained value except `updown`, error placement, bounds, and only on regular swanctl `*.conf` files. `persistence.metadata` strips the parsed detail, so comparisons and incident evidence are unchanged. `startup_inventory.swanctl_text` rebuilds text that the contract tokenizes identically, with each statement on its original line. `strongswan_view` runs `app/strongswan_updown.evaluate` from `swanctl.conf` (Debian) or `/etc/strongswan/swanctl/swanctl.conf` (RPM). Absent paths and include-directory listings are observed only from a complete collection. Unreported, unparsed, truncated, non-`.conf`, symlinked and outside files stay unobserved, so they produce blocking gaps.
- **Startup Files:** `swanctl.conf` shows each connection · child, its command, shell syntax, whether it runs (as root, discarded for a multi-line value, or empty) and its source line. It states that charon's account is assumed root and that plugin enablement and connection loading are not assessed. Other parsed files, older agents and unparsed files are explained. The Coverage catalog counts parsed files per layout.
- **Validation:** `tests/test_strongswan_statements.py` has 44 cases, including a 2,400-configuration seeded differential where raw and rebuilt text evaluate identically (commands, gaps, notes, files, fingerprint). Four of five targeted mutations were caught at first. The fifth (keyword `include` from a quoted string) survived until a fuzz fragment was added; now it fails. A sixth was equivalent, so that redundant agent check was removed. Startup, scope, persistence, ClamAV, Dovecot and strongSwan suites: 879 passed, 40 skipped. `tests/ui_startup_strongswan.cjs` checks escaping, accounts, gaps and 320/768/1440 px layouts.
- **Remaining for #1624:** legacy `ipsec.conf` `leftupdown`/`leftfirewall`, `strongswan.conf` updown plugin enablement (including the Debian-family `/etc/strongswan.conf` and `/etc/strongswan.d`), charon's observed account, package provenance and AI classification.
