# Native capped SQLite triage benchmark (#1605)

Roadmap A fixture for the
[Windows lock-adapter investigation](https://github.com/StealthCat/MrPatchy/issues/1032#issuecomment-7200597647).
Use the **Native capped SQLite AI benchmark** workflow in GitHub Actions
and select the ref to benchmark. When the workflow definition changes in a pull
request, its verification run benchmarks the exact pull request base. This
keeps a new runner definition separate from the application being measured.

The Ubuntu 24.04 job runs six serial/four-slot pairs and alternates which
configuration starts first. Each capture uses the existing temporary SQLite
database, the loopback provider, eight investigations, synthetic pricing and
the same latency and retained-history settings as the Windows investigation.
The job checks all pairs with the existing capability comparator before
uploading the raw captures, series and runner provenance. No deployment
database, remote server or provider credentials are required.

Use the per-pair reports to check reservation and reconciliation sample counts
and tails. Read the series median alongside the range and the reported
provider overlap. A small fixture with 12 receipts per configuration can
have p95 equal to the slowest observation. Runner and dependency differences
can affect comparisons with older captures. The workflow records fixture
measurements. Production-equivalent throughput, native MySQL timing and
scoring admission performance remain open.
