# Checkpoint: kdump crash-capture hook contract (#1538)

Roadmap F (startup and scheduled-task awareness), issue #1538.

## 2026-11-25 — increment 1: pure contract

**Delivered:** `app/kdump_hooks.py` and `tests/test_kdump_hooks.py`.

The contract takes the captured `/etc/kdump.conf` text and read-only metadata for `/etc/kdump/pre.d`, `post.d` and `emergency.d`. It returns:

- whether `kdumpctl` accepts the configuration;
- the ordered list of programs the capture environment runs as root, with their arguments;
- what a failure of each one does;
- the directory entries that are not installed, and why;
- explicit coverage gaps.

Semantics were read in kdump-utils at upstream `7bf4714` (`kdumpctl`, `mkdumprd`, `kdump-lib-initramfs.sh`, `dracut/99kdumpbase/kdump.sh`, `module-setup.sh`):

- **Order.** `kdump_pre` runs before `pre.d/*`, which is the reverse of the kdump.conf manual. Next come the dump (`core_collector`, word-split, default `makedumpfile -l --message-level 7 -d 31`; for a makedumpfile collector the capture script may rewrite `-F` and append `--num-threads`, which is reported as an observation), `post.d/*` with the dump status, and `kdump_post` with the dump status. On a capture failure, the error handler runs `emergency.d/*` and then `kdump_emergency`.
- **Failures.** A non-zero `kdump_pre` exit skips the dump and runs the final action. Every other hook failure only warns.
- **Hook values.** These are executed as one quoted word, so a value with arguments names a nonexistent path. This is reported as an observation, and for `kdump_pre` it suppresses the dump.
- **Directory entries.** Only non-hidden entries with an execute bit are installed. A directory or device that passes `-x` is reported as not run.
- **Refusals.** `kdumpctl` refuses unknown, deprecated, empty and repeated options, more than one dump target and a `dracut_args` value with more than one `--mount`. A refused configuration runs nothing.

**Validation:** 10 unit tests pass, and `ruff --select F` is clean.

**Remaining:**

- Collector wiring: read-only capture of the configuration and listings.
- Startup inventory and UI presentation, AI classification of custom entries, and native acceptance on RHEL and Fedora.

**Coverage gaps:**

- The loaded initramfs may predate the current files.
- Other `kdumpctl` checks are not assessed.
- Glob collation is assumed to be byte order.
- Hook contents and writability are not read.

**Compatibility:** none. These are new files only, with no schema, API or UI change.

## 2026-11-27 — increment 3: parsed kdump.conf hooks in Startup Files

**Delivered** (branch `claude/magical-goodall-dxwb17`), following the #1390 increment-3 pattern:

- `target/agent.py` `parse_kdump_conf()` parses the hashed bytes of `/etc/kdump.conf` when the controller
  requests parsed jobs (`cron_jobs`). It mirrors `app/kdump_hooks.assess()` for the configuration alone:
  `read -r` splitting, `#` cuts, one quote pair, accepted/deprecated options and kdumpctl refusals. Nothing
  is run. A symlink is recorded and not followed or parsed.
- Only the `kdump_pre`/`kdump_post`/`kdump_emergency` programs and the `core_collector` argv (or the
  default collector, line `null`) are stored, in capture order, with stage, failure effect and contract
  observations. A refused configuration stores only each refusal's line, option name (64 characters) and
  reason code, and no hooks. Programs use the cron best-effort redaction, control characters are
  escaped, and output is bounded to 512 characters and 32 collector arguments. Text over 64 KiB, with
  2048 or more lines, not UTF-8 or containing NUL bytes yields `parsed: false`.
- `app/persistence.py` `validate_kdump()` strictly validates the report: exact keys, the one path,
  regular files, canonical hook order and per-source stage, args, failure effect and observations,
  `starts` consistent with refusals, and strictly increasing refusal lines. `metadata()` drops the detail,
  so baseline comparison still uses hashes and metadata only.
- `app/startup_inventory.py` shows the hooks, counts them in the catalog row (also "refused by
  kdumpctl" and "not reported by this agent version"), makes them searchable and updates the coverage gap.
  `app/static/server.js` renders the sequence table, or a refusal notice.
- **Contract fix:** `app/kdump_hooks.assess()` split `core_collector` with `str.split()`. A value made only of
  non-IFS whitespace, such as a vertical tab, raised `IndexError` on main. It now splits on the capture
  shell's default IFS (space, tab, newline).

### 2026-11-27 — increment 3 review fix: line cutoff counts an unterminated final line

A [read-only review](https://github.com/StealthCat/MrPatchy/pull/1631#issuecomment-7208765694) of `a2e8f49` found that the
2048-line cutoff counted newline characters only. With 2047 newlines and an unterminated final line, the agent reported
`parsed: true` and a hook on line 2048, and the controller then rejected that report. The agent and `kdump_hooks.assess()`
now count an unterminated final line as a line. Every reported line number therefore stays below 2048, matching the
advertised "2048 or more lines" rule. Six boundary cases pass each agent report to the controller, including 2047-line
positive cases for a hook and for a refusal. The two over-limit cases from the review fail on `a2e8f49`.
