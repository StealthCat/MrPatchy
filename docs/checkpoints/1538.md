# Checkpoint: kdump crash-capture hook contract (#1538)

Roadmap F (startup and scheduled-task awareness), issue #1538.

## 2026-11-25 — increment 1: pure contract

**Delivered:** `app/kdump_hooks.py` and `tests/test_kdump_hooks.py`.

The contract takes the captured `/etc/kdump.conf` text and read-only metadata for `/etc/kdump/pre.d`, `post.d` and `emergency.d`. It returns:

- whether `kdumpctl` accepts the configuration;
- the ordered list of programs the capture environment runs as root, with their arguments;
- what a failure of each one does;
- the directory entries that are not installed, and why;
- explicit coverage gaps.

Semantics were read in kdump-utils at upstream `7bf4714` (`kdumpctl`, `mkdumprd`, `kdump-lib-initramfs.sh`, `dracut/99kdumpbase/kdump.sh`, `module-setup.sh`):

- **Order.** `kdump_pre` runs before `pre.d/*`, which is the reverse of the kdump.conf manual. Next come the dump (`core_collector`, word-split, default `makedumpfile -l --message-level 7 -d 31`; for a makedumpfile collector the capture script may rewrite `-F` and append `--num-threads`, which is reported as an observation), `post.d/*` with the dump status, and `kdump_post` with the dump status. On a capture failure, the error handler runs `emergency.d/*` and then `kdump_emergency`.
- **Failures.** A non-zero `kdump_pre` exit skips the dump and runs the final action. Every other hook failure only warns.
- **Hook values.** These are executed as one quoted word, so a value with arguments names a nonexistent path. This is reported as an observation, and for `kdump_pre` it suppresses the dump.
- **Directory entries.** Only non-hidden entries with an execute bit are installed. A directory or device that passes `-x` is reported as not run.
- **Refusals.** `kdumpctl` refuses unknown, deprecated, empty and repeated options, more than one dump target and a `dracut_args` value with more than one `--mount`. A refused configuration runs nothing.

**Validation:** 10 unit tests pass, and `ruff --select F` is clean.

**Remaining:**

- Collector wiring: read-only capture of the configuration and listings.
- Startup inventory and UI presentation, AI classification of custom entries, and native acceptance on RHEL and Fedora.

**Coverage gaps:**

- The loaded initramfs may predate the current files.
- Other `kdumpctl` checks are not assessed.
- Glob collation is assumed to be byte order.
- Hook contents and writability are not read.

**Compatibility:** none. These are new files only, with no schema, API or UI change.

## 2026-11-26 — increment 2: built-in collection of `/etc/kdump.conf`

**Delivered:** `/etc/kdump.conf` joins built-in startup scope, following the reviewed #1530, #1390 and #1535 increment-2 pattern.

- `target/agent.py`: `PERSISTENCE_FILES` hashes the file as metadata only. A symlink is recorded, not followed, and nothing is parsed or run. `PROMOTED_PERSISTENCE_FILES` keeps a saved custom path equal to it valid and covered once.
- `app/persistence.py`: `ADDITIVE_BUILTIN_SCOPE` lets a baseline from an older agent stay comparable. The file is listed as `newly_in_scope` / `not_in_baseline`, never as `added`. Neighbouring paths (`/etc/kdump`, `/etc/kdump/pre.d`, `/etc/sysconfig/kdump`, `/etc/default/kdump-tools`, `.rpmnew`) and downgrades stay non-additive.
- `app/startup_inventory.py`: the label "kdump crash-capture configuration" and a coverage gap.
- `app/startup_catalog.py`: an RPM-family, event-triggered, system-scope, metadata-level `kdump` mechanism.

**Dependency:** stacked on #1590 (#1535 increment 2). Both PRs edit the same single-line scope tuples, so this PR should be integrated after #1590.

**Validation:** `tests/test_kdump_scope.py` has 17 tests. 7 fail on the #1590 head `f2578682`, and all 17 pass on the branch. The agent test writes `kdump_pre`, `kdump_post`, `kdump_emergency` and `core_collector` commands that would create a marker file, and asserts the marker never appears. A mutation that makes `/etc/kdump` additive instead of `/etc/kdump.conf` fails 4 tests. 641 related tests pass.

**Remaining:**

- Read-only listings of `/etc/kdump/{pre,post,emergency}.d` and feeding the collected bytes to `app/kdump_hooks.py`.
- Startup-view presentation of parsed hooks, AI classification of custom entries, and native acceptance on RHEL and Fedora.
- The Debian kdump-tools configuration is not covered by the contract.

**Compatibility:** no schema, route, authentication, scheduling or response-authorization change, and no file content is collected. After the agent update, existing baselines list `/etc/kdump.conf` as newly in scope until an administrator approves a new baseline.
