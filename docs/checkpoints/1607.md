# Checkpoint: ClamAV event-command contract (#1607)

Roadmap F (startup and scheduled-task awareness), also feeding roadmap E. Issue
[#1607](https://github.com/StealthCat/MrPatchy/issues/1607).

## 2026-11-26 — increment 1: pure contract

**Delivered** (branch `claude/magical-goodall-ck40k0`): `app/clamav_event_commands.py`, a pure
contract. It takes captured `clamd.conf` and `freshclam.conf` text and reports which
administrator-configured commands ClamAV 1.5.4 runs on its own events:

- clamd `VirusEvent`, on every detection. It runs as `User` with the primary group only when
  clamd starts as root, through `execle("/bin/sh", "sh", "-c", ...)`. clamd waits for the command
  under a mutex shared by every scanning thread. `%v` becomes the detected signature name,
  unescaped, and `%f` a fixed message. The environment holds only the two `CLAM_VIRUSEVENT_*`
  variables and a malformed bare `PATH` value, so `sh` uses its built-in search path.
- freshclam `OnUpdateExecute`, `OnErrorExecute` and `OnOutdatedExecute`. They run through
  `system()` as `DatabaseOwner` (default `clamav`). Outside daemon mode, `EXIT_<n>` makes
  freshclam exit with that status instead of running anything. In daemon mode the
  outdated-version command is the `OnUpdateExecute` text (upstream passes the wrong option). The
  first `%v` is replaced with an empty string.
- The `optparse` config-file rules: 1023-byte `fgets` chunks, short-line and comment skipping,
  `Example`, quoting, case-sensitive names and long-option aliases, unknown options rejecting the
  file, deprecated options ignored, value regexes applied before inline-comment removal, `#`
  truncating even inside quotes, all-`#` values that crash the parser, and first occurrence wins.

Unobserved configuration, an unknown start account or freshclam daemon mode, a `daemon` key in
the file, NUL bytes, over-limit input and parser-crash input are blocking gaps. A result with any
gap is not `complete`. Command-line overrides, start-time checks beyond the parser and account
resolution are fixed limitations. `origin` is `not_assessed` and `authorizes_response` is always
false.

**Validation:** 16 tests in `tests/test_clamav_event_commands.py`, with native cases from Ubuntu
24.04 `clamav 1.5.4+dfsg-0ubuntu0.24.04.1`. clamd and freshclam were traced with strace
(`execve`, `setgroups`, `setgid`, `setuid`), and parser cases were checked with `clamconf -c`. A
seeded differential run against native `clamconf -c` agreed on acceptance, parser crashes and
stored values for 700 random clamd and 800 random freshclam files, 1,500 in total, including
63 native parser crashes. Five targeted mutations each fail the tests.

**Compatibility:** new files only. No schema, route, UI, auth, scheduling, agent or
response-authorization change.

**Remaining under #1607:** agent collection of both files, Startup Files display, package
provenance, AI classification, and native confirmation of the outdated-version path (it is
source-derived and needs a mirror that announces a newer version).

## 2026-11-27 — increment 2: collector capture

**Delivered** (branch `claude/vibrant-tesla-dkxnts`, stacked on #1639): agents hash the ClamAV
configuration as built-in startup scope. Nothing is parsed or run. The files are metadata and SHA-256
only, like the other built-in startup files.

- Debian family: the `/etc/clamav` directory (built-in root). It holds `clamd.conf`, `freshclam.conf`
  and the `onupdateexecute.d` and `onerrorexecute.d` directories.
- RPM family (EPEL): the `/etc/clamd.d` directory (built-in root, `scan.conf` for `clamd@scan`) and
  `/etc/freshclam.conf` (built-in file).
- `app/persistence.py`: all three paths are additive built-in scope. An earlier complete inventory
  still compares within its own scope and lists them as newly covered.
- An administrator could previously store `/etc/clamav`, `/etc/clamd.d`, `/etc/freshclam.conf`, or a
  file inside either directory, as a custom path. Such a stored path is now covered by built-in scope,
  through #1639's `PROMOTED_PERSISTENCE_ROOTS` and `PROMOTED_PERSISTENCE_FILES`, so saved monitor
  policies stay valid and the files are inventoried once. A stored path equal to a new built-in path
  stays in scope and keeps comparing. A stored file inside a new directory is listed as
  `previously_custom` and keeps comparing. Siblings such as `/etc/clamav-unofficial-sigs`,
  `/etc/clamd.conf` and `/etc/freshclam.conf.rpmnew` stay ordinary additional scope.
- `app/startup_inventory.py` labels the three paths and states the parsing gap.
  `app/startup_catalog.py` adds the `clamav` event mechanism with per-family locations.

**Validation:** `tests/test_clamav_scope.py` (35 cases) fails 16 of them on the base (#1639 head merged
with main `3a06f2e`) and passes with the change. The other startup and persistence suites pass. CI ruff
selections and `check_version --allow-unversioned` pass.

**Compatibility:** no schema, route, UI, auth, scheduling or response-authorization change. Agents
that report the new paths add up to a few entries on hosts with ClamAV installed, within the existing
256-entry inventory budget.

**Next increment:** agent-side parsing of the hashed `clamd.conf` and `freshclam.conf` bytes through
`app/clamav_event_commands.py` and the Startup Files display. The contract covers the Debian paths
only; the RPM-family files need native evidence before they are parsed.
