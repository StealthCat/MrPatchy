# Source identity in triage benchmark reports (Roadmap A, #1553)

## 2026-11-26

The disposable AI triage benchmark records `source_commit` when Git reports
clean tracked source at both ends of a capture and the commit is the same.
The source check is outside the measured stages. It reports only the full
object ID. It leaves the field absent for dirty tracked source, an export
without a Git checkout, or a failed Git check. Untracked capture files can
live beside the checkout. Record dependency and fixture settings separately.

The single-pair comparator keeps each report's source commit with its
baseline or candidate output and validates the field when present. Older
reports still compare without the field. Different source commits are
expected in a before/after comparison. Existing workload, control and
capability checks still decide whether a pair can be compared.

On main `6a408d3ae1db7151713107d0cb22fae3396dab42`, a clean synthetic
capture completed two subjects and three fixture calls without recording its
source commit. The worker tests cover clean and dirty Git checkouts, missing
Git, source exports, labeled and historical comparisons, and malformed
values. Matched production performance remains a separate acceptance step.
