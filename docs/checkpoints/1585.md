# Link update-scoring batches in one write (#1585)

## 2026-11-26

- Roadmap A follow-up to #594. The update scorer sets the run ID on the
  admitted batch with a single primary-key UPDATE, then commits before
  provider access. The transaction rolls back if fewer rows match than
  expected.
- On v1.110.0, the five scoring outcomes in the regression each performed
  three score reads. The worker version performs two, with the same
  committed run links and outcome states. A partial-link simulation checks
  rollback and provider refusal.
- The shared scorer lock, authorization, staged calls, package evidence and
  retry rules are unchanged. This reduces a database round trip on the
  scoring path. The crash gap between admission and run linkage,
  independent scoring execution and measured fleet throughput remain open.
