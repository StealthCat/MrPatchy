# Checkpoint: rsnapshot command contract (#1530)

Roadmap F (startup and scheduled-task awareness), issue
[#1530](https://github.com/StealthCat/MrPatchy/issues/1530).

## 2026-11-25 — increment 1: pure contract

**Delivered** (branch `claude/magical-goodall-yer5qx`): `app/rsnapshot_commands.py`, a pure
contract that takes file records for `/etc/rsnapshot.conf` and its `include_conf` files and
reports which programs rsnapshot 1.4.5 runs as the invoking user (root from the packaged
`/etc/cron.d/rsnapshot`):

- `cmd_preexec`/`cmd_postexec` (last valid assignment wins; extra tab fields are silently
  dropped; run from `$HOME`; a non-zero exit aborts rsnapshot);
- `backup_script` (run from `<snapshot_root>/tmp/`; failure rolls the destination back) and
  `backup_exec` (path never checked; `required` failure aborts);
- backtick `include_conf` commands, which run while the configuration is parsed, at every
  invocation including `configtest`, even when the configuration is later rejected;
- program paths (`cmd_rsync`, `cmd_ssh`, `cmd_cp`, `cmd_rm`, `cmd_logger`, `cmd_du`,
  `cmd_rsnapshot_diff`, `linux_lvm_cmd_*`) with their absent-key defaults;
- Perl's one-string `system()` shell-versus-`execvp` decision and argv for each command.

Configuration errors (spaces instead of tabs, relative hooks, unknown directives, include
cycles, missing includes, ordering rules for `snapshot_root` and `cmd_ssh`) are reported, and a
rejected configuration marks backup-time commands `runs_only_if_config_accepted`. Unobserved or
unknown files, NUL bytes, over-limit input, include depth and backtick-include output are named
coverage gaps; a result with any gap is not `complete`.

**Validation:** 21 tests in `tests/test_rsnapshot_commands.py`. Ten reproduce native runs of
rsnapshot 1.4.5-2 on Ubuntu 24.04 (perl 5.38.2, rsync 3.2.7) traced with
`strace -f -e trace=execve`: hook order and working directories, the dropped tab field, shell
selection, last-wins, continuation joining (including `#`-led continuations), required versus
optional `backup_exec` failure, backtick include running under `configtest` with a rejected
configuration, the self-include abort, and the final-`0` parse stop.

**Compatibility:** new files only. No schema, route, UI, auth, scheduling, agent or
response-authorization change.

**Remaining under #1530:** agent collection of the configuration and includes, startup catalog
and provenance integration, linkage to the cron entry that invokes rsnapshot (and alternate
`-c` files), UI, and AI classification of the reported commands.

## 2026-11-26 — increment 2: built-in collection of `/etc/rsnapshot.conf`

**Delivered** (branch `claude/magical-goodall-rjjptx`), mirroring #1390 increment 2:

- The agent's built-in startup scope (`target/agent.py` `PERSISTENCE_FILES`) now includes
  `/etc/rsnapshot.conf`. It is hashed as metadata only. A symlink is recorded, not followed,
  and nothing in it is parsed or run, including backtick `include_conf` commands.
- The path joins the reviewed `persistence.ADDITIVE_BUILTIN_SCOPE`. A baseline that an older
  agent collected stays comparable within its own scope. The file is listed as `newly_in_scope`
  and shown as `not_in_baseline`, not as `added`. Neighbouring paths such as
  `/etc/rsnapshot.conf.default` or `/etc/rsnapshot.d` are not additive.
- The path joins `PROMOTED_PERSISTENCE_FILES`. A saved monitor policy that already listed it as a
  custom path stays valid, and the file is covered once.
- Startup Files labels the file "rsnapshot configuration". The startup mechanism catalog gains a
  metadata-level, schedule-triggered `rsnapshot` mechanism. A coverage gap states that the
  pre/post-exec, backup script, backup_exec, program-path and backtick include commands are not
  parsed in this view yet. It also states that included files, alternate `-c` configurations and
  the invoking cron entry or timer are not evaluated.

## Acceptance (increment 2)

- `tests/test_rsnapshot_scope.py` has 14 tests. Seven fail on main and all pass on the branch.
  They cover:

**Compatibility:** no schema, route, auth, scheduling or response-authorization change, and no

## 2026-11-28 — increment 3: agent-reported lines evaluated in Startup Files

- **Agent** (`target/agent.py` `parse_rsnapshot_conf`): from the exact hashed bytes, splits
  `/etc/rsnapshot.conf` into the logical lines rsnapshot 1.4.5 `parse_config_file()` reads: `#` comments,
  blank lines, continuation joining with one tab, the final-`0` stop and tab-separated fields (at most
  four). Only `include_conf`, `cmd_preexec`, `cmd_postexec`, `backup_script`, `backup_exec`, the program
  paths (`cmd_rsync`, `cmd_ssh`, `cmd_cp`, `cmd_rm`, `cmd_logger`, `cmd_du`, `cmd_rsnapshot_diff`,
  `linux_lvm_cmd_*`), `snapshot_root` and the first two `backup` fields keep values. Every other directive
  keeps its name and whether it had a value. Command fields and tab-less lines get the cron best-effort
  credential redaction; values are cut at 512 characters and names at 120. Redaction or cutting is
  reported per line as `inexact`. At most 1024 statements (`truncated` beyond). Non-UTF-8 or NUL bytes
  report only an error. Nothing is run, and no `include_conf` file is opened.
- **Controller** (`app/persistence.py` `validate_rsnapshot`): strict shape, path, line-order, field and
  continuation checks; values only for retained directives; parsed detail excluded from `metadata()`.
- **View** (`app/startup_inventory.py` `rsnapshot_view`): rebuilds text with every logical line at its
  original line number and runs `rsnapshot_commands.assess_config`. Contract gaps, the statement limit
  and inexact lines are blocking gaps. Included files are not collected, so each `include_conf` stays a
  blocking `file_not_observed` gap. Never a safety verdict; `authorizes_response` is false.
- **UI** (`app/static/server.js` `startupRsnapshot`): commands with kind, argv or `/bin/sh -c`, trigger,
  failure effect and line; program paths with defaults and superseded values; a notice when rsnapshot
  rejects the configuration (no backup command runs, backtick includes still do); errors and gaps;
  explanations for older agents, undecodable files and symlinks.

### Validation (increment 3)

- `tests/test_rsnapshot_agent_view.py`: packaged Ubuntu config and native cases evaluate identically
  through the agent path and on the full text; 1500 seeded random configurations (comments, blanks,
  continuations, space/tab separators, final `0`, kept/other/unknown directives) match; redaction,
  limits, undecodable input and 18 validator corruptions.
- `tests/ui_startup_rsnapshot.cjs`: escaped rendering, rejected configuration, gaps, older agents,
  no horizontal scroll at 320/768/1440.
