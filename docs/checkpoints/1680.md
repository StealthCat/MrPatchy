# #1680 — strongSwan reports that rejected a host's startup inventory

Roadmap F (startup and scheduled-task awareness) defect repair, P2. Follows #1624 / #1674 (v1.128.0).

## 2026-11-27 — repair

**Cause.** Two agent/controller disagreements in the swanctl statement stream made
`persistence.validate` raise for the whole inventory, so Startup Files and file-status/known-good
resolution were unavailable for every entry on the host:

- `include ""` is reported as an include with an empty pattern, which `validate_swanctl` rejected.
  The pure contract also mis-read it, as a literal include of the containing directory
  (a blocking `file_not_observed` gap). Native strongSwan 5.9.13 (Ubuntu 24.04 `charon-systemd`,
  `swanctl --load-conns`) logs `no include pattern specified, ignored` and loads the rest of the file.
- When the 2000-statement cap stopped a file, the agent had already counted the value of the setting
  it could not emit, so a file of valued settings reported `dropped=2001`, above the validator bound.

**Delivered.**

- `app/strongswan_updown.py` (contract version 2): an empty include pattern is ignored, with an
  `include_pattern_empty` note, as strongSwan does.
- `target/agent.py`: `dropped` is counted only after the setting is emitted. The empty-include
  statement shape is unchanged.
- `app/persistence.py`: empty include patterns are valid. A truncated report may carry one extra
  dropped value, so reports already queued from v1.128.0 agents are accepted; non-truncated reports keep
  the strict bound. Truncated files remain a blocking `statements_truncated` file-level gap in the view.
- `app/startup_inventory.py`: empty patterns are not turned into include-directory listings.

**Validation.** `tests/test_strongswan_incomplete_reports.py` (9 tests, all failing on main `7a0e386`):
contract versus native behaviour, producer → validator → view for both shapes, the legacy over-count
accepted only when truncated, a seeded differential with empty includes, and the
`/api/hosts/{id}/security/startup-inventory` page returning the unrelated cron entry and the truncation
gap. 1062 startup/persistence/agent/strongSwan tests pass locally.

**Remaining.** None for this issue. Not changed: the contract still reports an `unbalanced_braces`
gap at the last line with content when rebuilt text drops trailing blank lines (display line only).
