### HAProxy program-section contract — worker checkpoint #1555 (roadmap F, increment 1)

In master-worker mode (Ubuntu and Debian start HAProxy with `-Ws`, as root), the master process forks each `program` section's `command` itself. The global `user`/`group` settings drop privileges for workers only. A program without its own `user` therefore runs with the master's identity, which is root under the packaged unit. A changed `haproxy.cfg` or a file added to a configuration directory can start a new long-running root process.

- **Increment 1:** the pure `app/haproxy_programs.py` takes the captured config files in load order. For each `program` section it reports the id, the argv, whether execvp searches PATH, `user`/`group` as written, whether supplementary groups are dropped, `start-on-reload`, source locations and any `master-worker` line in the config.
- **Semantics:** these come from HAProxy 2.8.30. The relevant code is `cfgparse.c` `readcfgfile`, `tools.c` `parse_line` (ENV, DQUOTE, SQUOTE, BKSLASH, SHARP and WORD_EXPAND), `cfgcond.c` integer terms, and `mworker-prog.c` `cfg_parse_program`, `cfg_program_postparser` and `mworker_ext_launch_all`:
  - lines have no length limit. A NUL byte, or a last line without LF, is fatal. Leading `isspace` characters are skipped;
  - words split on unquoted white space, including `\v` and `\f`. `#` starts a comment even in the middle of a word. Backslash escapes are `\ `, `\\`, `\t`, `\n`, `\r`, `\#`, `\'` and `\"` outside single quotes, `\$` inside double quotes and `\xHH`; any other backslash stays literal. A line holds at most 64 words, and a trailing empty word is not counted;
  - `$VAR` expands only inside double quotes. `.LINE`, `.FILE` and `.SECTION` are computed from their source location, and the `${name-default}` and `${name[*]}` forms are supported for them;
  - `.if`/`.elif`/`.else`/`.endif` work as follows. Integer-constant conditions use `strtol` base 0, so octal and hex are accepted. A masked parent skips nested blocks. `.elif` after `.else`, a lone `.else`/`.endif` and an unterminated block are all fatal;
  - `no`/`default` shift the words. Only `option`, `log` and a few global flags accept them, so `no command` is fatal;
  - section state starts empty in every file;
  - a duplicate program id is fatal. The last `command` replaces earlier ones, and its argv stops at the first empty word. For `user` and `group` the first value wins, and a repeat only alerts. `option start-on-reload` is on by default, and `default option` leaves it unchanged.
- **Fail closed:** the following are blocking gaps:
  - environment variables;
  - `.if` conditions other than integer constants;
  - scope directives;
  - `external-check` and `option external-check` in proxy sections, which are deferred to increment 2;
  - tokenizer errors, unknown directives, `.alert`, unsupported modifiers and out-of-section lines;
  - malformed, duplicate or command-less programs;
  - over-limit input.

  `complete` is false whenever any of these is present. No result is a safety verdict.
- **Validation:** `tests/test_haproxy_programs.py` has 10 tests. The first is a native run: Ubuntu 24.04 haproxy 2.8.30-0ubuntu0.24.04.2 was started as root with `haproxy -W -f a.cfg -f b.cfg`, and each program recorded its argv and uid/gid. The four started programs matched the contract's argv[1:], uid and gid exactly. That run covered quoting and escapes, a mid-word `#`, unexpanded `$HOME`/`${.SECTION}` outside double quotes, `.LINE`/`.FILE`/`.SECTION`, first-wins `user`, argv truncation at `""`, `.if 0`/`.elif 1`/`.else`, last-wins `command`, a second file with `group` only (gid 65534, uid 0) and `no option start-on-reload`. Twelve rejected configurations were also checked against `haproxy -c` exit status 1.
- **Remaining after increment 1:** per-backend `external-check command`/`path` health-check scripts, delivered in increment 2 below.

### Increment 2 — external-check health-check commands

HAProxy workers fork `external-check command` once per check interval for every server with health checks, in each proxy whose check type is external. The worker runs it inside the global `chroot` with the global `user`/`group`. Without a global user it keeps the identity HAProxy started with, which is root under the packaged unit. A `defaults` section can make every later backend, in every later file, run the same command.

- **Contract (version 2):** `evaluate()` now also returns `external_checks`. Each entry is one listen/backend whose check type is external. It gives the command, the defining location (including the inherited `defaults` line), the argv template `[command, proxy addr, proxy port, server addr, server port]`, `PATH` (the configured path or empty), whether execvp searches it, the environment mode (`preserve-env`), the chroot, the run-as user/uid/group/gid, whether supplementary groups are dropped, the fork gate and the proxy's `server`/`server-template` lines. `external_check_global` reports the global `external-check`, `preserve-env` and `insecure-fork-wanted` state.
- **Semantics (HAProxy 2.8.30 `extcheck.c`, `cfgparse.c` post-parser, `proxy.c` `proxy_preset_defaults`, `cfgparse-global.c`, `haproxy.c` `set_identity` and the worker `RLIMIT_NPROC` step):**
  - every check-type option (`httpchk`, `tcp-check`, `ssl-hello-chk`, ...) replaces the single check type. `no`/`default option external-check` and extra arguments are fatal;
  - `external-check command|path` take one non-empty word, and the last one wins;
  - regular proxies copy the type, command and path of the last `defaults` section, which persists across files. A new `defaults` section starts empty;
  - after parsing, an external check without global `external-check` or without a command is fatal. A command without a leading `/` and without a path is fatal even when the check type is not external. Otherwise a command without the external type is ignored. `defaults` sections are not post-parsed and frontends have no servers;
  - without `insecure-fork-wanted` the worker sets `RLIMIT_NPROC` to 0. A non-root worker then cannot fork the check, but a root worker can. The last `[no] insecure-fork-wanted` wins.
- **Fail closed (blocking gaps):** `external_check_malformed`, `external_check_not_enabled`, `external_check_without_command`, `external_check_relative_without_path`, `defaults_from_unmodelled` (named `defaults ... from` inheritance) and `global_identity_ambiguous`. The last applies when a repeated `user`/`uid` or `group`/`gid` exists and an external check is reported: HAProxy skips the repeat only when the first value resolved to a non-zero id, and names are not resolved. The former `external_check_unmodelled` gap is removed.
- **Unobserved:** per-server activation (`check`, `default-server`, `no-check`, `server-template` counts) and `disabled` proxies are not evaluated, so every proxy with an external check type is listed with its server lines.
- **Validation:** `tests/test_haproxy_programs.py` now has 16 tests, 5 of them new. Ubuntu 24.04 haproxy 2.8.30-0ubuntu0.24.04.2 was started as root with `haproxy -W -f a.cfg -f b.cfg`. A recording check script showed `id -u/-g/-G`, `PATH`, `HAPROXY_PROXY_NAME` and argv, and the contract matched all four proxies that ran. This covered a command and option inherited from `defaults` across files, a relative command with `external-check path`, an `option httpchk` replacement, a bind address in argv, and `nobody`/`nogroup`. Variant runs covered root without `insecure-fork-wanted` (the check ran as 0:0), `nobody` without it ("Failed to fork ... missing 'insecure-fork-wanted'"; nothing ran), user-only (65534:0, groups not dropped) and `preserve-env` without master-worker. Fourteen configurations rejected by `haproxy -c` (exit 1) and four accepted ones are replayed. The five new tests fail against the increment 1 module.
- **Remaining:** Lua `lua-load` files, collection of `/etc/haproxy` and the unit's `-f` arguments, startup-inventory wiring, provenance and AI classification.
