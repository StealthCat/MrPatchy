# Checkpoint: Samba smb.conf command contract (#1580)

Roadmap F (startup and scheduled-task awareness), issue
[#1580](https://github.com/StealthCat/MrPatchy/issues/1580).

## 2026-11-26 — increment 1: pure contract

**Delivered** (branch `claude/magical-goodall-uf89to`): `app/samba_commands.py`, a pure
contract that takes captured `smb.conf` text and captured `include =` targets. It reports
each configured command with its parameter, share (or `None` for global), `[homes]`/`[printers]`
template, command string, account, trigger, source file and line, share availability and
whether a failing `root preexec`/`preexec` refuses the connection:

- share commands: `root preexec`/`root postexec` as root, `preexec` (synonym `exec`) and
  `postexec` as the connecting user, with `root preexec close`/`preexec close`;
- global commands (user/group/machine scripts, share and printer management, shutdown,
  quota, `panic action`, `passwd program`, `username map script`, `check password script`,
  `message command`, `wins hook`, `log nt token command`). The account is `root` only where
  the Samba 4.19 parameter documentation says so, `guest` for `message command`, and
  `not_assessed` otherwise;
- `lib/util/tini.c` line handling (comments, backslash continuation, whitespace-run
  collapse, one-character trim) and `loadparm.c` section handling (`[global]`/`[globals]`
  compared like `strwicmp`, shares snapshot the `[global]` defaults when first created,
  reopened shares, ignored global-only parameters in shares, textual includes, skipped
  missing includes, the 100-deep include limit, and whole-file rejection for a missing `]`,
  an empty name or an invalid tracked boolean).

Unobserved configuration or includes, `%`-substituted, relative or `registry` includes,
`config file`, `config backend = registry`, `copy =`, NUL bytes, invalid UTF-8 and
over-limit input are blocking gaps; a result with any gap is not `complete`. Printing,
`dfree`, `magic script` and AD DC command parameters are listed in
`configured_not_evaluated` when set. `origin` is `not_assessed` and
`authorizes_response` is always false.

**Validation:** 21 tests at first (28 after the review fix) in `tests/test_samba_commands.py`, replaying Ubuntu 24.04
`samba 2:4.19.5` `testparm -s -v` results, plus a live `testparm` differential that runs
when Samba is installed. A local differential over 44 fixtures (including 40 generated
ones) matched `testparm` on every share/parameter and on whole-file rejection. A native
`smbd -F` run with `smbclient` guest connections showed an inherited global `root preexec`
and a share `root postexec` writing uid 0, `preexec` writing the guest uid 65534, and an
`available = no` share refusing the tree connect without running its command.

**Review fix (same increment):** an independent review of `160dccf` found two cases where the
contract reported `complete` with no root command while native `smbd` ran one as uid 0. Both
are fixed on this branch:

- smbd adds the implicit `IPC$` share (and `ADMIN$` with `enable asu support`) after loading,
  from the final `[global]` defaults (`lp_add_ipc` in 4.19.5 `loadparm.c`). Its inherited
  `root preexec`/`preexec` run on every client connection. The contract now reports these
  commands with `implicit_share: true`. An explicit `[IPC$]` keeps its creation-time snapshot
  and is forced available.
- `force user` and `admin users` change the account for `preexec`/`postexec`. `force user =
  root`, or a name that resolves to uid 0 in an optional captured `/etc/passwd`, is reported
  as `root`. Another resolved name is `forced_user`. A `%` macro, an unknown name or a missing
  `passwd` gives `not_assessed` with a blocking `unresolved_force_user` gap. `admin users` is
  reported in `root_for_admin_users`, and those commands join `root_commands`.

Native `smbd -F` runs confirmed both: IPC$ ran the final `[global]` `root preexec` as uid 0 and
`preexec` as uid 65534. `force user = root`, `force user = daemon` and `admin users = nobody`
ran `preexec` as uid 0, 1 and 0. An explicit `[IPC$]` with `available = no` still ran its own
snapshot. The test count is now 28.

**Compatibility:** new files only. No schema, route, UI, auth, scheduling, agent or
response-authorization change.

**Remaining under #1580:** agent collection of `/etc/samba/smb.conf` and its includes,
`%` macro expansion, `copy =` evaluation, printing/`dfree`/`magic script` and AD DC
commands, the `smbd`/`nmbd` service command line (`-s`/`--configfile`), startup
catalog/provenance integration, UI and AI classification.

## 2026-11-28 — increment 2: metadata-only built-in scope

**Delivered** (branch `claude/confident-einstein-4azodc`): agents hash the Samba configuration as
metadata-only built-in startup scope. That covers the `/etc/samba` directory on both families
(smb.conf, files it includes there, and other files such as smbpasswd or lmhosts) and the
RPM-family `/etc/sysconfig/samba` options file (`SMBDOPTIONS`, `NMBDOPTIONS`) as a nested
built-in file. Nothing is parsed or run, and no file content is stored.

- `/etc/samba` is in `PERSISTENCE_ROOTS`, `PROMOTED_PERSISTENCE_ROOTS` and
  `ADDITIVE_BUILTIN_SCOPE`, so a saved custom `/etc/samba`, or a path inside it, is promoted and
  inventoried once.
- `/etc/sysconfig/samba` is in `PERSISTENCE_FILES`, `NESTED_PERSISTENCE_FILES` and
  `PROMOTED_PERSISTENCE_FILES`. `/etc/sysconfig` is not built-in, so a saved custom one stays
  valid and leaves the file to built-in scope.
- Both startup catalogs label the paths (`samba`, `samba_sysconfig`). A coverage gap says that
  the root preexec/postexec, preexec/postexec and global commands are not yet evaluated. It also
  names what is not observed: includes outside `/etc/samba`, the registry backend,
  `/var/lib/samba`, and unit or command-line options.
- The Debian-family `/etc/default/samba` is not included: current Debian and Ubuntu packages do
  not read it.

**Validation:** `tests/test_samba_scope.py` has 28 tests. 13 fail on main `92a39af` and all
pass on the branch. The suites that reference the scope tuples or catalogs give 1081 passed.

**Remaining:** agent parsing of the hashed bytes with the increment 1 contract, the Startup Files
view of commands, shares and accounts, provenance and AI classification.
