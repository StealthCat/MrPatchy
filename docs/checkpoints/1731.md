# Retained native slow-provider triage benchmark records (#1731)

The [native manual workflow](https://github.com/StealthCat/MrPatchy/actions/runs/46136656468)
ran six alternating serial and four-slot pairs per database on Ubuntu 24.04 at
worker commit `3beb4936ae7c4725c6d936b5864d547ef50ac1d5` from #1728.
Each directory contains the 12 original raw captures, original paired series
and runner provenance. The retained file bytes match the published archives.

Run `python -m pytest -q tests/test_ai_benchmark_native_records.py` to replay
both series along with the earlier native captures. At 4,500 ms per response
and a rate limit of 1,000 starts per hour, all six pairs on each backend recorded
peak provider concurrency of one with one slot and three with four slots.
Each capture completed eight investigations and four follow-ups, retained
12 input stages, and settled 12 calls for 240 synthetic micro-USD.

The median within-pair elapsed difference (four slots minus one) was −20.481
seconds on SQLite and −21.718 seconds on MySQL. The earlier [150 ms captures](1697.md)
peaked at one provider request in all runs. Each series pairs identical
workloads within its own delay profile. The loopback provider, simulated SSH
delay, synthetic prices and job-local databases leave production throughput,
real provider spend and remote database behavior open.
