# Checkpoint: PostgreSQL server command contract (#1597)

Roadmap F (startup and scheduled-task awareness), issue
[#1597](https://github.com/StealthCat/MrPatchy/issues/1597).

## 2026-11-26 — increment 1: pure contract

**Delivered** (branch `claude/vibrant-tesla-a6vc26`): `app/postgresql_commands.py`, a pure
contract that takes captured text of a PostgreSQL 16 main configuration file, the files and
`include_dir` listings it includes and the data directory's `postgresql.auto.conf`, and
reports, as the server's operating-system account:

- the shell commands the server runs through `/bin/sh -c`: `archive_command`,
  `restore_command`, `recovery_end_command`, `archive_cleanup_command` and
  `ssl_passphrase_command`, with the effective file and line, superseded assignments, when
  each runs and the conditions it depends on;
- the code it loads: `archive_library`, `shared_preload_libraries`,
  `session_preload_libraries` and `local_preload_libraries`;
- whether the server would start: any configuration error (syntax, include failure, bad
  modelled value) is fatal at start, and so is `archive_mode` with `wal_level = minimal`.

It models the `guc-file.l` scanner (flex longest match, so `foo.conf` is a qualified ID and
not a value), `DeescapeQuotedString`, error recovery, case-insensitive names, `include`,
`include_if_exists`, `include_dir` filtering and `strcmp` order, nesting depth 10, the
two-pass `data_directory` lookup with `postgresql.auto.conf` read last,
`replace_percent_placeholders` errors, `archive_command`/`archive_library` exclusivity and
`SplitDirectoriesString` (an invalid list is only logged and loads nothing).

Unobserved files or directories, unknown data directory, NUL bytes and over-limit input are
gaps, and a result with any gap is not `complete`. A running server's current values,
recovery/standby signal files and other parameters are not modelled. `origin` is
`not_assessed` and `authorizes_response` is always false.

**Validation:** 22 tests in `tests/test_postgresql_commands.py`. The parse fixtures replay
`postgres -c config_file=... -C <name>` on Ubuntu 24.04 PostgreSQL 16.15 (38 differential
cases, all matching, including canonicalized relative includes). The runtime fixtures replay `pg_ctl start` plus `pg_switch_wal()` on a
real cluster: the `%x` placeholder FATAL, "both archive_command and archive_library set",
the `wal_level = minimal` start failure, the logged invalid preload list, and a working
`archive_command`. Mutations that make `include_if_exists` strict, drop the qualified-ID
token or ignore `archive_library` each fail a test. Each pass opens at most 256 files, so
`include_dir` fan-out becomes a gap.

**Remaining:** collect the files in startup scope (the Debian `/etc/postgresql/*/*/` and RPM
data-directory layouts), show the commands in Startup Files, package provenance, AI
classification and native acceptance.
