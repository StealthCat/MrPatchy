# Checkpoint: PostgreSQL server command contract (#1597)

Roadmap F (startup and scheduled-task awareness), issue
[#1597](https://github.com/StealthCat/MrPatchy/issues/1597).

## 2026-11-26 — increment 1: pure contract

**Delivered** (branch `claude/vibrant-tesla-a6vc26`): `app/postgresql_commands.py`, a pure
contract that takes captured text of a PostgreSQL 16 main configuration file, the files and
`include_dir` listings it includes and the data directory's `postgresql.auto.conf`, and
reports, as the server's operating-system account:

- the shell commands the server runs through `/bin/sh -c`: `archive_command`,
  `restore_command`, `recovery_end_command`, `archive_cleanup_command` and
  `ssl_passphrase_command`, with the effective file and line, superseded assignments, when
  each runs and the conditions it depends on;
- the code it loads: `archive_library`, `shared_preload_libraries`,
  `session_preload_libraries` and `local_preload_libraries`;
- whether the server would start: any configuration error (syntax, include failure, bad
  modelled value) is fatal at start, and so is `archive_mode` with `wal_level = minimal`.

It models the `guc-file.l` scanner (flex longest match, so `foo.conf` is a qualified ID and
not a value), `DeescapeQuotedString`, error recovery, case-insensitive names, `include`,
`include_if_exists`, `include_dir` filtering and `strcmp` order, nesting depth 10, the
two-pass `data_directory` lookup with `postgresql.auto.conf` read last,
`replace_percent_placeholders` errors, `archive_command`/`archive_library` exclusivity and
`SplitDirectoriesString` (an invalid list is only logged and loads nothing).

Unobserved files or directories, unknown data directory, NUL bytes and over-limit input are
gaps, and a result with any gap is not `complete`. A running server's current values,
recovery/standby signal files and other parameters are not modelled. `origin` is
`not_assessed` and `authorizes_response` is always false.

**Validation:** 22 tests in `tests/test_postgresql_commands.py`. The parse fixtures replay
`postgres -c config_file=... -C <name>` on Ubuntu 24.04 PostgreSQL 16.15 (38 differential
cases, all matching, including canonicalized relative includes). The runtime fixtures replay `pg_ctl start` plus `pg_switch_wal()` on a
real cluster: the `%x` placeholder FATAL, "both archive_command and archive_library set",
the `wal_level = minimal` start failure, the logged invalid preload list, and a working
`archive_command`. Mutations that make `include_if_exists` strict, drop the qualified-ID
token or ignore `archive_library` each fail a test. Each pass opens at most 256 files, so
`include_dir` fan-out becomes a gap.

**Remaining:** collect the files in startup scope (the Debian `/etc/postgresql/*/*/` and RPM
data-directory layouts), show the commands in Startup Files, package provenance, AI
classification and native acceptance.

## 2026-11-27 — increment 2: built-in startup scope

**Delivered** (branch `claude/confident-einstein-niukpf`): agents hash the Debian-family
`/etc/postgresql` directory as built-in startup scope, as metadata and SHA-256 only. That covers
`postgresql.conf`, `conf.d`, `pg_hba.conf`, `pg_ident.conf`, `start.conf`, `pg_ctl.conf` and
`environment` for every `<version>/<cluster>`, which is the layout `pg_createcluster` creates
(Ubuntu 24.04, postgresql-common 257, PostgreSQL 16).

- `/etc/postgresql` is additive to earlier baselines (`ADDITIVE_BUILTIN_SCOPE`). Saved custom
  paths inside it are promoted and still compared.
- Both catalogs label it (`postgresql`). The startup catalog also lists the RPM-family
  `/var/lib/pgsql/data` location, which shows as `not_collected`. A coverage gap says what is not
  collected.
- **Not built in, on purpose:** the data directory. It holds `postgresql.auto.conf` on both
  families and `postgresql.conf` on RPM, but it also holds the whole database cluster, and its
  path depends on the version. A fixed built-in file such as `/var/lib/pgsql/data/postgresql.conf`
  would also invalidate any saved custom path at `/var/lib`, `/var/lib/pgsql` or
  `/var/lib/pgsql/data`, because custom paths must not contain built-in scope. Administrators can
  add those files as custom paths, which still works (tested).

**Validation:** 30 tests in `tests/test_postgresql_scope.py`. 12 of them fail against main's
sources and pass with the change. One test hashes the real `/etc/postgresql/16/main` cluster
created by `pg_createcluster` on Ubuntu 24.04 (it is skipped where no cluster is installed).
The SHA-256 matches the file's bytes, and no gaps are reported. A synthetic cluster shows that
no configuration text or `pg_hba.conf` content is stored, a symlinked include is recorded but not
followed, a FIFO is excluded and nothing is run.

**Compatibility:** additive scope only. No schema, route, UI, auth, scheduling or
response-authorization change. Older agents keep their earlier scope.

**Remaining under #1597:** collecting `postgresql.auto.conf` and the RPM-family configuration
from the data directory, agent-side capture of parsed settings into the increment-1 contract,
Startup Files display, package provenance, AI classification and native acceptance.

## 2026-11-28 — increment 3: agent statements and Startup Files display

**Delivered** (branch `claude/friendly-hopper-2o8cm4`): agents reduce every regular file under
`/etc/postgresql` and the controller evaluates them with the increment-1 contract.

- `target/agent.py` `parse_postgresql`: the agent reduces each file from the exact hashed bytes. It
  uses a port of the contract's `guc-file.l` lexer and statement loop, including error recovery and
  the 100-error limit per file. Only these keep their values:
  - `include`, `include_if_exists` and `include_dir`;
  - the settings the contract reads: the five commands, the four library settings, `archive_mode`,
    `wal_level`, `ssl`, `ssl_passphrase_command_supports_reload`, `data_directory` and
    `dynamic_library_path`.

  Every other assignment is dropped and counted. This covers `primary_conninfo` passwords, pg_hba
  and pg_ident lines. A rejected line keeps only its line number. Commands get the best-effort
  credential redaction used for cron commands. NUL bytes or non-UTF-8 text mean nothing is parsed.
  Over 2000 statements or a value over 4096 characters marks the file truncated.
- An `include_dir` under `/etc/postgresql` carries a read-only listing: names and `lstat` kinds,
  up to 256 entries. Debian's stock empty `conf.d` is therefore observed rather than guessed. The
  agent opens every path component from `/` with `O_NOFOLLOW|O_DIRECTORY` relative to its parent
  descriptor and inspects entries with `dir_fd` and no link following, so nothing outside
  `/etc/postgresql` is opened or listed. A listing is unobserved (`null`, a `directory_not_observed`
  gap) when the path is not lexically normal, leaves the root, passes through a symlink, contains a
  symlinked entry (PostgreSQL would follow it), exceeds the entry limit or fails with an error other
  than ENOENT (absent) or EACCES (unreadable). Directories outside `/etc/postgresql` stay unobserved.
- `app/persistence.py` `validate_postgresql` validates each report strictly: exact keys, increasing
  line numbers, at most 100 errors, kept names only, bounded values and well-formed listings.
  `metadata` excludes the statements from comparisons and incident evidence.
- `app/startup_inventory.py` rebuilds text that the contract parses identically. Each
  `/etc/postgresql/<version>/<cluster>/postgresql.conf` row gets a `postgresql` view with:
  - commands, with when they run, their conditions, whether they are active and their file:line;
  - libraries;
  - start blockers, configuration errors (without the rejected text) and blocking gaps.

  Older agents show "not reported by this agent version". Absent paths count as observed only in a
  complete collection. Truncated, symlinked and outside files are unobserved. The view always has
  `complete: false`, `origin: not_assessed` and `authorizes_response: false`.
- `app/static/server.js` `startupPostgresql` renders the view. The catalog label counts parsed files.

**Validation:** `tests/test_postgresql_agent_view.py` has 58 tests:
- a 1200-case seeded differential between raw text and the agent-reduced rebuild path, plus a
  stock-like case;
- 400 lexer fuzz cases against the contract tokenizer;
- secret dropping and redaction, limits and 24 malformed-report rejections;
- complete and incomplete collections, symlinked, outside, truncated and older-agent files;
- an end-to-end agent run that executes nothing;
- 14 listing-containment tests (temporary directories and mocked `os.open`/`os.stat`): the empty
  in-scope directory, lstat kinds, symlinked ancestors and entries (never followed), non-normal and
  out-of-root paths (nothing opened), per-component `O_NOFOLLOW` descriptor-relative opens, open
  error mapping and the entry limit. Twelve of them fail with the `627959d` agent.

Mutations that drop backslash escaping in the rebuild, or the agent's 100-error stop, each fail
tests. `tests/ui_startup_postgresql.cjs` covers escaping, timing, activity, libraries, errors and
gaps at 320, 768 and 1440 px.

**Remaining under #1597:** collecting `postgresql.auto.conf` (every evaluation currently carries a
blocking `auto_conf_not_observed` gap) and the RPM-family data-directory configuration. Also native
acceptance of the agent path on a real cluster, package provenance and AI classification.
