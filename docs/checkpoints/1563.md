# Roadmap A checkpoint #1563 — update-scoring batch age

Administrators can see the oldest observed update age in the existing **Update
importance** timing summary. Each tracked scoring batch can produce one sample,
computed at selection from the earliest availability observation among the
packages selected for that batch. The age starts with the observed pending
update, including time before scoring was enabled or became eligible. Admission,
provider and result-persistence measurements remain separate.

A selected package without a usable availability timestamp leaves the batch
without an age sample. A measured zero remains zero. Existing completed runs
supply no age sample without a retained event. No package names, source
timestamps or input evidence are added to the timing result or provider request.
The metric shares ordinary diagnostic retention and the existing administrator
access. Process triage keeps its existing stage list.

The regression checks selected versus already-scored packages, valid zero,
missing and future timestamps, redacted input and scoring summary output. The
responsive UI check loads both activity summaries and verifies that only update
scoring shows the new row and its explanation. Broader scoring admission and
production throughput acceptance remain open.
