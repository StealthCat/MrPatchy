# Checkpoint: Monit control-file program contract (#1611)

Roadmap F (startup and scheduled-task awareness). Issue
[#1611](https://github.com/StealthCat/MrPatchy/issues/1611).

## 2026-11-26: increment 1, pure contract (in progress)

**Delivered so far** on branch `claude/magical-goodall-439bgw`:

- `app/monit_programs.py`: a pure `resolve()`. It reports the `start`, `stop` and `restart program` commands, `exec` actions and `check program ... path` commands from captured monit control-file text. Each command comes with its service, argv and account (`uid`/`gid`, or the monit daemon's account). The lexing is ported from monit 5.33.0 `src/l.l`.
- `tests/test_monit_programs.py`: 10 tests. They replay native runs of Ubuntu 24.04 monit `1:5.33.0-2build2`:
  - `monit -v -t` parsed values
  - an argv/uid trace from `monit -I` with an exec action that records its arguments and `id -u`
  - comment handling

**Blocking gaps:**

- `include` (not resolved yet)
- unbalanced quotes
- unterminated commands
- empty commands
- `\0` escapes
- NUL bytes
- over-limit input
- configuration not observed
- unknown daemon account

`origin` is `not_assessed` and `authorizes_response` is always false.

**Known limits:**

- Grammar acceptance of the rest of the file is not evaluated. The error is a false positive: a reported command may never run if monit rejects the file.
- Programs are not checked for existence.
- uid/gid names are not resolved.

**Remaining for increment 1:**

- a source review of the `else if`/`repeat`/`timeout` option tails

**Later increments:**
