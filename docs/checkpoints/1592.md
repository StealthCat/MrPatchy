# Capped triage benchmark on v1.110.0 (#1592)

## 2026-11-26

Measured clean main `e8ad2b901c2becdb0de3379ffef3790c0953c690` with
Python 3.14.7 on Windows using a local compatibility adapter for Linux file
operations. The MySQL 8.4.13 server was native Windows and bound to loopback.
The SQLite 3.50.4 database was disposable. All model replies and SSH evidence
were synthetic. The fixture used the real daily-cap reservation and settlement
path with a synthetic price catalog and a UTC reset.

Each run admitted eight investigations on eight fixture servers and retained
1,000 older completed observations. Four investigations collected follow-up
evidence. The fixture simulated a 150 ms provider delay, 50 ms SSH delay and
15 ms receipt/usage persistence delay. Captures alternated serial-first,
four-slots-first and serial-first on each backend. The series comparator
accepted all six pairs. Every run completed eight assessments, retained all 12
input stages, made 12 loopback provider calls, and settled 12 reservations
totaling 240 synthetic microdollars. No run granted an approval.

Differences are four slots minus one slot, paired within each backend.

The four-slot fixture completed sooner on MySQL and later on SQLite. Both
backends reduced waiting in the executor while individual investigations took
longer. These runs do not isolate the cause of the SQLite result. Production
throughput, fleet workloads, same-server capped cases and Linux lock behavior
remain open.

### Reproduce and verify

Run the existing benchmark at the recorded source commit. For each backend
capture three matched pairs, switching `--concurrency` between 1 and 4 and
using the capture order above. For MySQL, change `--database` to `mysql` and set
`AI_BENCHMARK_MYSQL_URL` to a newly created, empty disposable database.

```bash
python tools/benchmark_ai.py --database sqlite --runs 8 --follow-up-runs 4 \
  --servers 8 --concurrency 1 --control-mode daily_cap --provider-delay-ms 150 \
  --ssh-delay-ms 50 --persistence-delay-ms 15 --retained-history-rows 1000
```

The [retained SQLite series](../benchmarks/ai-capped-v1110/sqlite-series.json)
and [MySQL series](../benchmarks/ai-capped-v1110/mysql-series.json) are generated
from the twelve adjacent raw reports. For each backend, pass its three
`SERIAL PARALLEL` file pairs to `tools/compare_ai_benchmark_series.py` using
one `--pair` per pair. The comparator checks workload equivalence before
reporting elapsed, throughput and stage timing differences.
