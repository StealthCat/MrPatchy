# Slow-provider paced triage benchmark (#1722)

The retained native paced captures for #1697 used 150 ms provider responses
and one start every 3.6 seconds. All captures recorded peak provider
concurrency of one. The loopback provider can now delay a response by up to
5,000 ms, which lets a fixture run longer than the shared start interval.
The comparator uses the same delay bound as the producer and still requires
the delay and workload evidence to match before comparing performance.

Use this fixture for a matched SQLite pair:

```bash
python tools/benchmark_ai.py --control-mode rate_and_daily --rate-per-hour 1000 --runs 4 --provider-delay-ms 4500 --concurrency 1 > serial.json
python tools/benchmark_ai.py --control-mode rate_and_daily --rate-per-hour 1000 --runs 4 --provider-delay-ms 4500 --concurrency 4 > parallel.json
python tools/compare_ai_benchmarks.py serial.json parallel.json
```

The default workload requests two follow-ups in each four-investigation run.
Compare the recorded peak provider requests alongside the settled receipts,
retained assessments and timing stages. The local Windows adapter is suitable
for testing overlap within one fixture process. Repeat the paired workload
with native Linux SQLite and a disposable MySQL database for platform-level
timing. Synthetic provider delays and prices do not measure production
throughput or provider spend.
