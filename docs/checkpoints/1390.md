## Increment 3: parsed commands in Startup Files

The first pure startup contract wired into Startup Files.

- `target/agent.py` `parse_tcp_wrappers()` parses the hashed bytes of `/etc/hosts.allow` and `/etc/hosts.deny` when the controller requests parsed jobs (`cron_jobs`, as for crontabs, at jobs and `/etc/anacrontab`). It mirrors `app/tcp_wrappers.resolve()`: `xgets()` continuations and the 2048-byte limit, column-0 comments, `split_at()` outside `[...]`, case-insensitive `ALL`/`EXCEPT`, option fields with `\:` escapes and the option errors that stop later options. Nothing in the files is run. A symlink is recorded and not followed or parsed.
- Only `spawn`, `twist` and `aclexec` commands are stored, with their daemon and client lists, the `user`/`group` options ignored by the Debian build and the runtime checks before them. Other option values (`setenv`, `banners` and so on) are never stored. Commands use the cron best-effort redaction, control characters are escaped, and output is bounded to 64 commands, 512 characters per command and 32 tokens of 255 characters per list. Text that is over 1 MiB, not UTF-8 or contains NUL bytes yields `parsed: false` and no commands.
- The agent also reports the first unconditional entry (`ALL` daemon and client lists, no `EXCEPT`) and whether any entry up to it names `aclexec`. The controller uses them for reachability: a command after an unconditional entry in its own file is shadowed, and every `hosts.deny` command is shadowed by an unconditional `hosts.allow` entry unless an `aclexec` up to it can unmatch it. When `hosts.allow` is not collected, is a symlink, was not parsed or comes from an older agent, `hosts.deny` reachability is shown as unknown, never as reachable. A `hosts.allow` that is missing (absent from the host) leaves `hosts.deny` reachable.
- `app/persistence.py` `validate_tcp_wrappers()` strictly validates the report: exact keys, the two paths only, regular files only, bounds, ordered lines before any reported error line, and allowed option names. `persistence.metadata()` drops the parsed detail, so baseline comparison still uses hashes and metadata only.
- `app/startup_inventory.py` shows the commands with reachability, counts them in the catalog rows, marks files from older agents as `not_reported`, makes them searchable and updates the coverage text. `app/static/server.js` renders a table with each option's effect.

### 2026-11-26 — increment 3 review fix: strict option-list member types

A read-only review of `e2d183e1` found that `validate_tcp_wrappers` hashed
`identity_options_ignored`/`after_runtime_checks` members during duplicate detection before
checking that they were allowed strings. A receipt with an unhashable member (a JSON object or
array) raised `TypeError` instead of the intended `ValueError` rejection. The validator now
checks each member's type and allowed name before duplicate detection. Eight malformed-member
cases (objects, arrays, `null` and integers in both lists) join the bad-receipt tests, and five
valid unique lists, including empty lists and every runtime option, are confirmed to pass.
All six unhashable-member cases raised `TypeError` on `e2d183e1`.
