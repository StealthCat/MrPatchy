# #1327 net-snmp snmpd program contract (roadmap F)

Increments 1 and 2 are recorded in

## 2026-11-28 — increment 3 (part): `-C` disables configuration loading

- **Change:** `evaluate_snapshot` in `app/snmpd_programs.py` now models snmpd's `-C` option.
  Before this change it reported a blocking `argv_config_not_modelled` gap. The contract version
  moves from 1 to 2, and snapshot results gain `default_configs_read`.
- **Semantics:** traced from net-snmp 5.9.4 source:
  - `agent/snmpd.c` handles `-C` by setting `NETSNMP_DS_LIB_DONT_READ_CONFIGS`, which
    `default_store.h` aliases as `NETSNMP_DS_LIB_DISABLE_CONFIG_LOAD`. It is a boolean, so its
    position among the options does not matter.
  - `snmplib/read_config.c` `read_config_files_of_type` returns at once when that flag is set.
    Neither the `snmpd` nor the `snmp` type is read from the search path or the persistent
    directory, and persistent backups are skipped too.
  - `includeSearch` goes through `read_config_files_of_type`, so under `-C` it reads nothing.
    The line is reported as `rejected` with reason `config_load_disabled`.
  - `read_configs_optional` does not check the flag. `-c` files are still read, before or after
    the (now empty) default pass, and so are their `includeFile` and `includeDir` lines.
- **Unchanged:** `evaluate`, which takes the caller's file order on trust, still reports `-C`
  as a blocking `argv_config_not_modelled` gap, because a caller-supplied order cannot show
  which files `-C` kept out. An unobserved environment still blocks, as do relative `-c`
  names, `-Y` and `--token=value`.
- **Validation:**
  - `tests/test_snmpd_programs.py` has 32 tests. The two new tests fail on main `38c41d6` and
    pass on this branch.
  - Native check against Ubuntu 24.04 `snmpd 5.9.4+dfsg-1.1ubuntu3.3`, run as root in a
    disposable container on loopback. The fixture used the same layout as the new test:
    `/etc/snmp/snmpd.conf`, `snmpd.local.conf`, a cross-type `[snmpd]` line in `snmp.conf`, an
    `includeSearch site.conf` target in `/etc/snmp`, and a `-c` file with `includeFile` and
    `includeDir`. The registered `nsExtendArgs` rows were walked with `snmpwalk`.
    - Without `-C`: `etc`, `local`, `site`, `cross`, `only`, `inc` and `dir` were registered.
    - With `-C -c /opt/mpsnmp/only.conf`: only `only`, `inc` and `dir` were registered.
      `-Dread_config:file` listed exactly `only.conf`, `inc.conf` and `d/one.conf`. snmpd logged
      `Included config 'site.conf' not found` for the `includeSearch` line.
  - The contract produces the same rows and read order for `-C`.
- **Remaining on #1327:** derive the type registration order (the cross-type `[snmpd]` line in
  `snmp.conf` stays a blocking `type_order_not_derived` gap), wider differential validation
  against the packaged snmpd (amd64 `SNMPLIBPATH` and `/var/lib/snmp`), then agent collection,
  a catalog entry, package provenance, persistence, UI and AI classification.
